## 2026-11-22 16:23-16:43 修复 8099 qq-official 前台卡「正在连接本地控制台」

**用户报障**：http://127.0.0.1:8099/qq-official 「连不上手机了，看不了硬件信息」。

### 根因（两块要分清，别误判成手机断线）
- 顶部状态栏（温度/CPU/内存/开机时长）走 8099 /api/phone/status → SSH 采集手机，实测 ok=true、50 个字段全有、手机 ping 4ms —— 手机根本没断，硬件数据采集是好的。
- 卡住的是中间 iframe，它嵌 127.0.0.1:8097（server/phone_console.py 适配层），8097 没在跑，一直显示「正在连接本地控制台…」。

### 为什么 8097 没在跑（两个真 bug，都已修）
1. web_app.py::_ensure_phone_console() 原来只做 TCP connect 探活 —— 端口被半死进程占着时 connect 成功就误判「已在运行」直接 return，永不重拉。改为探 http://127.0.0.1:8097/api/status 必须 200，且 Popen 后还要 HTTP 验证真的活了才报成功（web_app.py 约 1674 行）。
2. phone_console.py::ThreadingServer 没有 handle_error，浏览器关 iframe 就刷 ConnectionAbortedError traceback（4 次开关 10KB）。加 handle_error 吞 Reset/Aborted/BrokenPipe。

### 环境坑（排查时浪费了时间，记下来）
- 环境变量里同时有 HTTPS_PROXY 和 https_proxy（大小写重复）时，Windows 的 Start-Process 复制环境会报 ArgumentException「已添加项。字典中的关键字 HTTPS_PROXY...」，表现为「启动了没反应」。用之前先清掉小写变量。
- 本沙箱里任何外部启动的子进程都会随父 shell 退出被杀（Start-Process/Popen/CREATE_NO_WINDOW 全试过）。唯一能持久的是用 Bash run_in_background 起的进程，由它内部再拉 8097。最终 8099 PID 26088、8097 PID 26200，qq-official 与 api/status 全 200，隔 5 分钟仍稳定。

### 验证（截图 + 机器断言）
- Playwright 进 iframe：FRAMES 含 8097、首屏「已连接/运行中/WiFi 健康/CPU 使用率/内存使用」、零 console error、零 API 失败；截图 D:/AI/tools/pmdocker/work/qqo-overview.png、qqo-hardware.png。

- 8097 stderr 0 条 Traceback。
