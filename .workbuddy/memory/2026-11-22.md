## 10:0x 修复：日志页「0/1 条」（用户："日志是不是没接上"）

**根因（两条契约，缺一即全空白）**：
1. `GET /api/logs` 前端读 **`.list`**，旧实现返回 `{lines:[...]}` → `.list ?? []` 得到空数组。
2. 每条必须有**小写** `level` 且 ∈ `['trace','debug','info','success','warn','error']`；前端 `q.has(t.level) ? ... : false` 会把缺 level 的整条丢掉。旧 SSE 只推 `{line}` → **1 条进数组、0 条过筛 = 正是截图里的「0/1 条」**。
   附带：`scope`/`message` 必须是字符串（前端直接 `.toLowerCase()`，None 会抛）。

**落地（commit `2513fac`，本地已提交，push 被代理 502 挡住待重试）**：
- `phone_ops.read_logs_multi()`：**一次 SSH** 用 `echo '@@@SRC <id>'` 分块标记并发 tail 多源（`MERGED_SOURCES = bot/chat/error/conn`）。日志页没有源选择器，一屏看全才够排查；仍走 `LOG_SOURCES` 白名单、跳过需 sudo 的 syslog。实测 1 次握手 2.5KB/4 源。
- `phone_console` 五格式归一解析：A nonebot(`MM-DD hh:mm:ss [LEVEL] scope | msg`)、B 应用日志(`YYYY-MM-DD hh:mm:ss LEVEL [scope] msg`)、C syslog(`Nov 22 ... daemon.info ...`)、D 无级别(`conn` 的 ALIVE 行)、E dmesg(`[ 18.56]`)。**续行继承上一条时间戳**（bot.py 会打 `[qq_bridge] official_event_arrived ...` 这种无时间戳行），否则合并排序后分组错乱。
- `id = sha1(scope+line)[:16]` 稳定去重：`qq_bridge.log` 与 `qq_bridge_error.log` 内容大面积重叠，合并后靠它压重（实测 756 条里 error 源只剩 1 条独立行）；SSE 重连也不重复堆叠。
