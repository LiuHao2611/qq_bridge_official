## 10:45 🔴 事故：调息挂错层级，玩家「点按钮看不到恢复」

**用户报障**：「我看我的斗气和血量没有自动恢复呢，怎么回事」。

**证据（先查后修）**：
* 生产库 `regen_clock` 只有 1 行（用户 openid），`last_at` 是 44 分钟前 ——
  说明一上午只有一条命令触发过结算，其余点击全没走。
* 该玩家 lv30 hp 7282/10403、mp 635/5286，仍是残血。
* 日志无 `调息结算失败`、无 traceback —— 不是报错，是**根本没被调用**。

**根因**：调息结算挂在 `commands._player()`，但只有文本口令用它。
`__init__.py` 有 10 处、`button_dispatch.py` 有 2 处直接 `await store.get_player()`：
按钮点击、人物卡渲染、战斗回看卡、炼药卡翻页……全都绕过 `_player`。
用户日常点卡片，自然看不到恢复。

**修法（下沉到唯一底层入口）**：
* `Store.get_player()` 内统一调 `_maybe_regen(qq, p)`；口令/按钮/渲染条条生效。
* `_maybe_regen` 用 `importlib.import_module(__package__ + ".core")` 延迟取 core
  （core 不依赖 store，无环；不能 `from . import store` —— `__init__.py` 把包属性
  `store` 盖成了 STORE 实例）。
* ⚠️ **必须出锁再调**：`get_player` 原先 `async with self._lock: return ...`；
  改成先在锁内取值、出锁后 await `_maybe_regen`（后者要拿同一把锁写 regen_clock
  和 put_player，asyncio.Lock 不可重入，持锁调用会死锁）。
* `commands._player()` 里删掉 `_regen_tick` 调用，避免二次结算吞余数；
  `_LAST_REGEN` 改成 `from .store import REGEN_NOTICE as _LAST_REGEN` 别名，
  唯一源搬到 store（旁路缓存依旧不写玩家存档）。

**门禁**：`tests/test_doupo_regen.py` +1（14 条）
`test_direct_get_player_heals_like_buttons`：模拟按钮 dispatch，完全不经过
`commands._player`，直接 `store.get_player()` 必须恢复且另开实例重读一致。
反证：把 get_player 里的 `_maybe_regen` 注释掉 → 4 条红（含这条）。

**教训**：「所有读玩家数据的入口」的收敛点是 `Store.get_player()`，不是命令层
的 `_player()`。以后任何**每次读取都要生效**的逻辑（结算/过期/刷新）必须挂这里。

## 16:5x 战斗回看超长分页（用户「超长就分页」）

**为什么**：回合数无上限（HARD_ROUND_CAP=300），26 回合 4,964px / 300 回合 48,904px，

**做法**：`doupo_battle.split_pages()` 用 `_bubble_plan` 实测高度切页（`card_height()`

续页只留胜负徽标+逐招，副标题「第 x/N 页 · 回合 a-b」，每页都带 tip。
贪心后**二分容量均匀填充**（否则末页只剩一回合，实拍 2557/2539/443）；超上限按回合均分
+ `page["capped"]`，一回合都不丢（旧「尾巴堆末页」实测 39,937px 巨图，已否）。
`pic.split_pages()` 是唯一入口（`_PAGE_SPLITTERS`），渲染层不复制高度常量。
发送：官方 `Outgoing(images=[...])` 走既有 merge 内嵌**一条** markdown（按钮照挂），
NapCat `matcher.finish(*segs)` 多图片段；`finish_card`/`send_card_via_channel` 收
`bytes | list[bytes]`，单页逐字节不变。

**顺手修**：终局条数值列固定 150px，7~9 位敌血会压在轨道上 → 按本行实测宽度让位
（`max(END_VAL_W, txt_w+8)`），不截断数值。

capped、8 回合真实败场仍单页 2414。回归：commands119/menu75/card16/duel56/core31/
