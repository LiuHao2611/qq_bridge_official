## §一 斗技按钮点出旧版卡（用户实测 bug）→ 修 + 守门

用户：「有的斗技按钮点了之后回复的居然是旧版本斗技卡片……肯定不只是斗技，检查好所有按钮和对应口令」。

根因：`button_dispatch.dispatch_button()` 用 `getattr(card, "render_" + card_key)` **猜**渲染函数。
斗技卡 key 恰好叫 `skills` → 猜中 `render_skills`（2026-11-24 已退役的旧四槽详情卡），
而手打「斗技」走 `render_learned`（合并名录卡）。同一动作两条路出两张卡。

修法：新增 `button_dispatch._CARD_RENDER = {"skills": "render_learned"}` 显式表，
兜底改 `_CARD_RENDER.get(card_key, "render_" + card_key)`。顺带修两处同类不一致：
- 「查看」按钮（`use_text`）原本只回纯文本 → 走 `item_lookup` + `render_item_detail`，`send_key` 改 `item:<名>`；
- 「炼制傀儡」按钮（`puppet_text`）原本只回文本 → 传 `craft_report` 进 `cmd_craft_puppet`，炼成才出 `render_craft_for`。
新增局部 `send_key`，允许「卡片视图」与「按钮族」分离。

守门 `tests/test_doupo_button_card_parity.py`（42 PASS）：独立 BASELINE（17 条）vs 源码解析真值双向比对；
名字不同**不算通过**，必须静态证明按钮入口函数体真的调用了手打入口
（`render_battle_for`→`render_battle`、`render_codex_for`→`render_codex`）。

## §五 环境事故（非本轮代码）

部署后 `/api/qqo/status` 一直 `online:false`。根因：`Getaway info` 失败，
`httpx.ConnectError: [Errno -3] Try again` = musl `getaddrinfo` 返回 EAI_AGAIN。
`/etc/resolv.conf` 是 NM 的 dnsmasq（127.0.0.1），**冷缓存首次解析 2.5s**，启动瞬间 DNS 未热 → 适配器放弃。
处置：`nmcli connection up FourSeasons_Plus_XA` → 等 DNS 热（20 连测全 0ms）→ `rc-service qq-bridge restart` → 5s 上线。
教训：**`rc-service restart` 前后要确认 DNS 已热**，否则 QQ 适配器 `Failed to get gateway info` 后不会自愈。
另注：`warframe` 采集与 QQ 同一时刻失败，是判断「整机出网」还是「单服务」的现成探针。
