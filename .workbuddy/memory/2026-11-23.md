## 深度调研（第二轮，用户「开始做」→「先不改，整理详细文档」）

**产物**：`docs/斗破卡片渲染性能_深度调研与优化方案_2026-11-23.md`（498 行，v1.0，方案待拍板，代码零改动）。

**本轮推翻/修正了上一轮的三条判断，全部有实测**：

1. **瓶颈不在文字绘制**。cProfile（`tmp/probe_render_profile.py`）显示：gaussian_blur 占 45%、PNG 编码占 30%、文字 render 仅 2.6%。
2. **真机（手机）PNG 编码占 48.7%**（614ms/1262ms），是最贵单项——`Canvas.to_bytes()` 用 `optimize=True`（= 最高 zlib），骁龙835 最吃亏。改 `compress_level=6`：614→100.6ms，**体积仅 +4.4%**，且**逐像素字节差异 = 0**（实测确认无损）。
3. **「缓存键精简」建议撤回**。`probe_data_volatility` 证明操作后恰好只有 exp/gold/hp 变，这三者正是卡面显示值；剥离 key 会让玩家看到旧数字，属错误（违反禁止假数据）。

**核心新发现（因果链）**：卡片变慢的起点 = 11-22 主题改游戏风。按小时 p50：11-21~11-22 稳定 438~554ms；11-22 22:00 首现 1230ms；**11-23 14:00 → 1295ms（2.8×）**。原因：`doupo_ui.py` 有 8 处 GaussianBlur（暗角 r=40、天光 r=60、云纹、牌匾辉光 9/3），全服务于**只依赖主题色+尺寸+标题**的静态装饰。

**真机三段拆解（720×810，手机 Python 3.14 / PIL 13.0.0）**：
- 外壳 card_shell（含全部模糊）**527.5ms** / 内容层 120.5ms / PNG 编码 614.3ms = **1262ms**
- P0-1 编码参数：→749ms（−41%）
- P0-1+P0-2 外壳缓存：→**221ms（−82%）**

**架构优势**：12 个斗破模板全部走同一个 `UI.card_shell`，一处加 LRU 全卡受益；`_measure` 不依赖 data（高度固定），分层前提天然成立。缓存键=(主题配色,W,H,title,top,width)，与玩家数据无关，命中率近 100%；改主题色自动失效（内容寻址红利）。

**澄清**：线上 100% cache miss 不是缓存失效。`probe_png_determinism` 证明同 params 渲染字节 6/6 一致（编码确定）；`probe_data_volatility` 证明状态不变时 data 0/26 变。真因是样本内无「同玩家+同状态+同卡」的重复请求。故提高命中率收益有限，降低单次渲染成本才是稳收益。

**权威对照**：QQ官方素材管理(qqbot-media 90天滑动)项目已用且已加 md5缓存+落盘+配额自愈，发送侧无更快通道；Pillow 12.3/13.0 有 3~5.6× 优化但手机电脑均已 13.0.0（升级无收益，排除）；CDN shell/fragment + 内容寻址缓存支持 P0-2 与「不能剥离新鲜度字段」两条结论。
