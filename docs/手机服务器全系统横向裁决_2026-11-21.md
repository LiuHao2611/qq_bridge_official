# 小米6（sagit）24小时服务器 —— 全系统横向裁决

> 时间：2026-11-21
> 背景：用户否决"长期插电脑 USB NAT"，要求手机独立放一边、局域网+外网访问、SSH 维护、24 小时稳定。
> 本文是继 `手机服务器方案深度调研_2026-11-21.md`、`手机服务器完美方案深度调研_2026-11-21.md` 之后的**终局裁决**，推翻前两份中"pmOS 唯一 4/4"的结论。

## 一、为什么推翻 pmOS（关键证据）

前两份调研把 pmOS 捧为"唯一 4/4 达标"，建立在"修好 WiFi 就行"的假设上。本轮用**论坛交叉验证 + 手机实证**证伪了这个假设：

1. **不是缺固件**（手机 SSH 只读实证）：`/lib/firmware/qcom/msm8998/xiaomi/` 下 `mba.mbn`、`modem.mbn`、`wlanmdsp.mbn`、`modemuw.jsn`、`adsp.mbn`、`slpi_v2.mbn`、`ipa_fws.mbn`、`a540_zap.mbn` 全齐；`ath10k/WCN3990/hw1.0/` 下 `board-2.bin` + `firmware-5.bin` 齐。与 jhugo 5.5 WiFi README 逐项吻合。
2. **真卡点是 msm8998 主线的 modem 启动，社区至今未解**：
   - msm8998-mainline GitLab **issue #15**（2021 至今 open）："Sometimes modem just crashes on boot and cannot recover"，日志中时而 `remote processor is now up`、时而 `start timed out`——**本身时好时坏、不可靠复现**。
   - 99degree/linux《qcom modem kick start》："ATM there are some issue happened and caused modem to hang. More to come."
   - 我们实测：`echo start > remoteproc0/state` → `MBA booted → loading mpss → qcom-q6v5-mss 4080000: start timed out → Boot failed -110`；remoteproc0(MSS)=offline、r2(WCNSS)=offline、无 wlan0。
3. **MSA 修复的关系被澄清**：wiki 说 MSA_READY 修复（commit `737abcabe`，3 个 commit 共 18 行，6.11 进主线）针对的症状是"ath10k 打印 FW 信息后卡住"。我们的卡点比它更靠前（modem 都没起来）。所以即便上 6.11+MSA，也未必解决当前超时。
4. **6.11 内核是死路**：全论坛（XDA/Reddit/GitLab/GitHub/pmOS+Nura wiki）无任何人为 sagit 编译 6.11+；全部指向 degdag 2021 的 5.11/5.15 fork。sagit 已 archived、无活跃维护者。编 6.11 = 内核移植工程（rebase + DTS/USB/显示补丁），非"拉源码编译"。
5. **XDA "5.11 跑通 WiFi"帖的正确解读**：degdag 2021 帖确有 5.11.14 + 4 服务 + diag-router 的 WiFi 成功截图，但那是 **Android `/data/.stowaways` 挂载 pmOS.img 的混合方案**，配单独 45MB firmware.zip；不是我们现在的纯 pmOS 分区布局，且对照 issue #15 可知不稳定可复现。

**裁决**：pmOS mainline 卡在社区自己都没解决的 modem 启动，本质是"时好时坏"，**达不到 24h 稳定**。继续投入（排查 or 编内核）都是赌博。

## 三、三个真正可行的候选（按"24h 稳定"排序）

### 候选 A：LineageOS 22.2 + root + Ubuntu chroot ★推荐
- **厂商 4.4 内核**：WiFi/电源/USB OTG/电池全通，这是"别人用手机做服务器"的成熟内核底座。
- **官方活跃维护**：ArianK16a / Nanhumly，2026-11-13 仍在出 nightly，月度安全补丁。
- **镜像已备**：`D:\AI\tools\lineageos\20261120\`，zip/boot/recovery/manifest 4/4 SHA256 与官方逐字节一致，`unzip -t` 无错。
- **跑服务方式**：root（Magisk/KernelSU）后 `Linux Deploy` 或手动 chroot Ubuntu arm64，跑原生 Python（避开 Termux 的 proot 性能损耗和 Bionic 兼容问题）。
- **保活要点**（多篇实战一致，见 twj0/xhh.club/OnlyBits 2025-2026）：
  - 关 Phantom Process Killer：`adb shell "device_config put activity_manager max_phantom_processes 2147483647"`（或 `settings put global settings_enable_monitor_phantom_procs false`）
  - `termux-wake-lock`（chroot 场景由宿主 Termux 持有）
  - 关电池优化、加 Doze 白名单、锁待机分组 Active
  - Wi-Fi sleep 策略设"从不"
- **电池保护**：小米6 无官方充电阈值节点，需查 `/sys/class/power_supply/battery/` 是否有 `input_suspend` / `charge_stop_level`；否则配智能插座定时断电或拆电池改直流。
- **外网**：Tailscale（私网）+ Cloudflare Tunnel/frp（公网，outbound-only），不依赖公网 IP。
- **风险**：需 root；Android 大版本更新后保活设置可能被重置，需重设。

### 候选 B：LineageOS 22.2 + Termux（不 root，最低改动）
- 同上内核/ ROM 优势，但用户态跑 Termux + proot-distro Ubuntu。
- 优点：不 root、可逆、上手最快。
- 缺点：proot 是 ptrace 用户态模拟，性能/权限受限（无真 namespaces/cgroups，Docker 不可靠）；qq_bridge 是 Python 栈可跑，但 NapCat 若需 Docker 会困难。
- 保活同候选 A 的四件套。
- **适合先验证**：刷机后进系统、装 Termux、跑通 Python + SSH，确认 WiFi/保活稳定，再决定是否 root 上 chroot。

### 候选 C：Ubuntu Touch 20.04
- Halium 9.0 / 内核 4.4.153，官方页面明写 WiFi/Hotspot/BT/NFC 全通、**24h+ 电池、7 天+ 稳定**、Waydroid 可用、有维护者、有 release channel（noble daily 2026-10-14）。
- **致命伤**：rootfs 只读、apt 禁用、开 rw 破坏 OTA → 跑不了任意 Python 服务/自定义守护进程。作为"服务器"不合格。
- 蜂窝数据/通话全坏（对服务器无所谓，但说明移植质量一般）；最后提交 2025-10-22。

### 已排除
- **pmOS mainline**：见第一节。
- **Sailfish OS 4.4.0 非官方移植**：架构合适（真 Linux + rpm + devel-su），但社区移植 4 年前、基线是 LineageOS 17.1（Android 10）、非官方无签名，长期维护存疑，作为 24h 生产服务器风险高。
- **MIUI 原生 + root**：网络/电源最稳，但底层停更在 Android 9/10，新软件兼容性逐年变差；需官方解锁（已解锁可行性取决于账号）。作为兜底可考虑。
- **Mobian / PureOS**：无 sagit 机型，不适用。

## 四、最终推荐

**走候选 A：LineageOS 22.2 + root + Ubuntu chroot**，分两步降低风险：
1. **第一步（可逆验证）**：TWRP → `adb sideload` 官方 LineageOS 22.2 zip → 进系统验证 WiFi 连接、SSH、保活四件套、续航。此步不 root、不迁移数据。
2. **第二步（确认稳定后）**：root + chroot Ubuntu arm64 → 迁移 qq_bridge（arm64 原生 Python）+ NapCat + 数据 → Tailscale/Cloudflare Tunnel 外网 → 电池保护 + 外部存活监控。

镜像已下载校验完成，随时可执行第一步。

## 五、硬件红线（任何方案都适用）
- 长期满电插电会鼓包：限充 80~85% 或拆电池改直流；先查 `input_suspend`/`charge_stop_level` 节点。
- 摘壳散热；手机 flash 不适合重写入，数据必须外部备份。
- 必须配外部存活监控（另一台机器定时 ping/check 服务），否则静默挂掉难发现。
