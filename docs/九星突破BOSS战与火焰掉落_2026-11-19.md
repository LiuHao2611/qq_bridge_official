> 用户口径（原话）：

## 1. 触发：什么是「九星突破」

九星 = 某个大境界的最后一颗星。突破它意味着**跨入下一个大境界**：

| 当前等级 | 突破 | 是否触发 |
|---|---|---|
| lv9 斗之气九段 | → lv10 斗者一星 | ✅ |
| lv10 斗者一星 | → lv11 斗者二星 | ❌（同境界升星） |
| lv18 斗者九星 | → lv19 斗师一星 | ✅ |
| lv93 半圣高阶 | → lv94 斗圣一星 | ✅ |
| lv102 九星斗圣 | → lv103 斗帝 | ✅（打完 BOSS 再走斗帝机缘判定） |

判定：`core.is_nine_star_breakthrough(p)` = 经验已满（`can_level`）**且** `realm_index(lv) != realm_index(lv+1)`。
经验不足不触发；普通升星不触发。此判定作为「突破前置条件」接在 `cmd_break`：九星时发「突破」先打 BOSS，胜了才真正升级。

## 2. 战力快照与 BOSS 强度

**快照**：触发瞬间 `copy.deepcopy(p)`，BOSS 数值一次锁定，战斗过程不再变化；`core.power(p)` 记为 `snapshot_power`（文案展示）。

**BOSS 生成**（`core.make_breakthrough_boss`）：
1. 用快照经 `monster_scaled()` 反解出一只「与快照势均力敌」的基准怪（`TTK_PLAYER=4.5` 回合）；
2. 在基准上放大血量/攻击：
   - `BOSS_BREAK_HP_MULT = 1.60`（更耐打，战斗拖到约 7-8 回合 → 斗气耗尽转普攻，消耗感就是难度）
   - `BOSS_BREAK_ATK_MULT = 1.15`（略疼）
3. `kind = 魂殿` → 复用既有 Boss 掉落（tier4 天材地宝 + 补血补气丹）。

⚠️ **不放大快照属性本身**：早期方案曾把快照的等级+1、六维+25% 再反解，结果低等级怪的攻击被反解到畸高（等级基数小），lv9/lv18 九星突破几乎必败、卡死新手。现方案难度主要来自耐久与消耗，保证各等级都能过（实测胜率 lv9≈100% / lv18≈93% / lv45≈40% / lv81+≈98%；失败不扣经验、可重试，故不会卡关）。

## 3. 战斗与结算（core.nine_star_breakthrough）

```
1. 快照 → 造 BOSS
2. fight(p, boss)  ← 既有回合制内核，自动服药/锁定物品口径与普通战斗一致
3. 胜 → roll_breakthrough_flame() 掉火焰 → level_up() 完成突破（回满血蓝）
   败 → 保留战斗损耗（掉血/耗药/耗斗气），经验不扣、不掉落、可再「突破」重战
```

**失败没有硬惩罚**：不扣经验、不扣金币、不掉等级；代价只是这一场消耗的斗气与药品。这是「有点难度」而非「惩罚性门槛」。

## 4. 火焰掉落：兽火概率高于异火

`core.roll_breakthrough_flame(p, rng)`（千分率）：

| 结果 | 概率 | 池 |
|---|---|---|
| 其他火焰（兽火/天然/人造/融合火） | 45%（`BOSS_FLAME_DROP_OTHER=450`） | `cfg.OTHER_FLAMES` 10 朵 |
| B 线数值异火 | 18%（`BOSS_FLAME_DROP_BONUS=180`） | `cfg.BONUS_FLAMES` 11 朵 |
| 无掉落 | 37% | — |

- **兽火/其他火焰概率是异火的 2.5 倍**（用户明确口径）。
- 融合新生火（琉璃莲心火/三千莲心火）在「其他火焰」池里权重 ×0.25，更稀有。
- **A 线隐藏彩蛋火 / S 线门槛火 / 帝炎不进池**——保护已拍板的三层投放设计（它们各有独立获取路径）。
- 掉落写入 `p["flames"][name] = 1`，与收服/支线同一真值；重复掉落折算药渣 ×30，不刷数值。
- **不新增任何存档字段**（最高声明：进库、单一真值、不塞 blob）。

## 6. 与其他玩法的关系
- **九星 BOSS 战是突破的前置战斗**，与「战斗」「爬塔」「周副本」完全独立，不改它们的数值/掉落。
- BOSS 复用 `fight` 内核与 `tower_mod` 之外的常规路径；怪物 `is_boss` 标记让既有 tier4 天材地宝 + 补血丹掉落逻辑自动生效（不另写一套）。
- 掉落的兽火/异火进入 `p["flames"]`，「异火」口令与卡片会列出已收服的（文本层已接入，卡片展示见 `card.build_flames_data`）。
