## 1. 问题①：力竭是假的 —— 确认属实，已改成真扣血

### 1.1 现象

自动爬塔（或手动爬塔、周副本）失败后提示「💀 力竭倒下」，但打开人物卡，气血仍是满值。

### 1.2 代码级取证（改前）

```python

fp["hp"] = int(st.get("temp_hp") if st.get("temp_hp") is not None
               else st_max["体力"])

```

```python

p["tower_checkpoint"] = max(...)

# ← 全程没有一处 p["hp"] = ...
```

调用方也只写会话：

```python

```

**结论**：塔与周本的战斗损耗只活在会话态里，`p["hp"]` 从未被写过。「💀 力竭倒下」纯属演出文案 —— 用户的判断完全正确。

### 1.3 方案取舍

两条路只能选一：

| 方案 | 代价 | 判定 |
|---|---|---|
| A. 改文案，不再许诺扣血 | 玩家输了一把却毫发无伤，战斗没有代价，等于塔可以无限白嫖 | ❌ 糊弄 |
| B. **真扣血**，落回存档 | 需要明确「什么时候扣、扣多少」 | ✅ 采用 |

**采用 B**，并把边界钉死：

- **只在力竭（打输）时扣**。胜利 / 主动「塔结算」收手不扣 —— 那是活着走下塔，塔的续航本来就由会话 `temp_hp` 承担。否则一轮爬塔里每层都得先嗑药，玩法被毁。
- **扣多少不另造标准**，直接复用普通战斗的战败规则。

## 2. 问题②：出卡变慢 —— 不是缓存坏了，也不是昨天改坏的

### 2.1 先建方法论：把一条出图口令切成三段

出图回执的真实耗时 = **渲染** + **素材上传** + **发送**。只看「从发口令到看见图」的总时长永远找不到瓶颈，所以在日志里按事件边界切段：

| 段 | 起点事件 | 终点事件 |
|---|---|---|
| 渲染 | 收到口令 | `pic_render ... render_ms=` |
| 上传 | `pic_render` | `official_image_button_merged`（或 `material_uploaded`） |
| 发送 | `merged` | `official_sent ... duration_ms=` |

分析脚本见本文附录 A。

### 2.2 五天数据：这两段根本没变

从 `~/qq_bridge/logs/qq_bridge.log` 按日聚合：

| 指标 | 11-22 | 11-23 | 11-24 | 11-25 |
|---|---|---|---|---|
| `pic_render` 次数 | 30 | 42 | 38 | 72 |
| 渲染 `render_ms` 平均 | 997 | 1148 | 1048 | 1175 |

## 3. 问题③：层号矛盾 —— 两套语义混用

### 3.1 病根

塔里有**两个不同的「层」**：

| 变量 | 语义 | 用途 |
|---|---|---|
| `st["floor"]` | **已通过层数** | 算奖励、推 `tower_paid_floor` / `tower_checkpoint` / `tower_best` |
| `tower_floor()["floor"]` | **正在打的那一层** | 战报标题、宝箱判定 |

推导用户的场景：

```
tower_checkpoint = 24        # 上次已通 24 层
start = cp + 1 = 25          # 文案：从第 25 层开始
st["floor"] = 24             # 进入 tower_floor，它算 floor = st["floor"]+1 = 25 ✅
第 25 层打输 → st["floor"] 不推进，仍是 24
tower_settle() → res["floors"] = 24
旧文案：txt.tower_down(res["floors"]) → 「止步第 24 层」   ❌ 自相矛盾
```

而**周副本一直是对的**（`commands.py` 用 `r["floor"]`）—— 两处判断标准本身就不一致，只是玩家先在塔上撞到。

### 3.2 修法

`src/plugins/doupo/doupo_text.py:830`

```python
def tower_down(fallen: int, cleared: int | None = None) -> str:
    fallen = int(fallen)
    if cleared is None or int(cleared) <= 0 or int(cleared) == fallen:
        return f"💀 力竭倒下，倒在第 {fallen} 层。"
    return f"💀 力竭倒下，倒在第 {fallen} 层（此前已通 {int(cleared)} 层）。"
```

一律报**倒下那一层**，必要时附「此前已通 N 层」；`cleared <= 0`（第一层就倒）或两者相等时不附，避免「已通 0 层」这种废话。

配套：

| 位置 | 改动 |
|---|---|
| `commands.py:3113` 手动爬塔 | `txt.tower_down(int(r["floor"]), int(res["floors"]))` |
| `commands.py:3398` 自动爬塔 | `txt.tower_down(last_floor, int(res["floors"]))` |
| `commands.py:3494` 周副本 | 统一走 `txt.tower_down(int(r["floor"]))`（原本就对，只是措辞对齐） |
| `commands.py:2986` 超时补结算 | 「止步第 N 层」→「**已通第 N 层**」（超时场景没有「倒下层」） |
| 两处「（最高 N 层）」 | →「（**最远已通** N 层）」，与「倒在第 N 层」不再打架 |

### 3.3 自洽性

`tower_checkpoint == 已通过层`，所以 **`checkpoint + 1 == 出发层 == 倒下层`**。玩家读到的三句话现在严丝合缝：

```
🗼 【试炼之塔】从第 25 层开始！          ← 出发
💀 力竭倒下，倒在第 25 层（此前已通 24 层）。  ← 倒下
　发「爬塔」从第 25 层再冲；              ← 重来
```

### 3.4 守门

- `test_exhaust_reports_the_floor_you_died_on` —— cp=24 的玩家在第 25 层失败，回执必须含「从第 25 层出发」「倒在第 25 层」，且**不含**「止步第 24 层」
- 变异反证：把 `tower_down` 入参改回 `res["floors"]` → 立刻红

## 4. 问题④：官方机器人支持哪些按钮类型

### 4.1 平台只有三种 `action.type`

依据：`bot.q.qq.com` v2「发送群聊消息 / 消息按钮」文档（本次核对时间为 2026-11-26）。

| `type` | 名称 | 点击后发生什么 | `data` 内容 | 适用场景 |
|---|---|---|---|---|
| **0** | 跳转按钮 | 客户端打开网页 / 小程序（识别 scheme） | https 链接 | 文档、反馈表、分享 |
| **1** | 回调按钮 | 客户端不发消息，向后台投递 `INTERACTION_CREATE`，`data` 原样送到 | 任意字符串（可以是内部哨兵） | 机器人要处理的动作 |
| **2** | 指令按钮 | 自动在输入框插入 `@bot + data`（群聊）；`enter=true` 才直接发送，且**仅单聊可用** | 真人可输入的完整口令 | 帮玩家省打字 |

本项目改造前**只用过 type=1**，另外两种能力一直闲置。

### 4.2 平台硬约束清单（踩过或核对过的）

| 约束 | 说明 | 我们的处理 |
|---|---|---|
| `label` ≤ 10 字符 | 超了截断或拒收 | `render_data.label = b.label[:10]` |
| 每行 ≤ 5 按钮、≤ 5 行 | 平台上限 | `wrap_button_rows()` 折叠尾部；样例正好 5 行 |
| `permission` **必须显式给** | 留空不是「所有人可点」，而是「谁也不许点」——按钮渲染正常、点得下去，客户端回「无权限操作」，**没有任何错误码** | 一律 `Permission(type=2)`（所有人） |
| `enter` 仅单聊可用 | 群里传 `true` 会被拒/忽略 | 指令按钮恒 `enter=False`（`b581522` 修正） |
| `group_id` 分组变灰只对 type=1 生效 | 同组一个按钮点过后其它变灰 | 不设 `group_id`，让所有按钮一直可点 |

## 附录 A：日志三段计时脚本（一次性排障用）

```python
# 把线上 qq_bridge.log 的出图链路切成 render / upload / send 三段
import re, statistics
from datetime import datetime
from pathlib import Path

rows = []
pat = re.compile(r"^(\d{4}-\d\d-\d\d \d\d:\d\d:\d\d)")
for ln in Path("qbl.log").read_text(encoding="utf-8", errors="replace").splitlines():
    m = pat.match(ln)
    if not m:
        continue
    t = datetime.strptime(m.group(1), "%Y-%m-%d %H:%M:%S")
    for k in ("pic_render", "material_uploaded", "official_image_button_merged", "official_sent"):
        if k in ln:
            rows.append((t, k, ln))
            break

last, seg = None, []
for t, k, _ in rows:
    if k == "pic_render":
        last = t
    elif k == "official_image_button_merged" and last:
        seg.append((t - last).total_seconds())
        last = None
seg.sort()
print("上传段 n=%d 平均=%.1fs 中位=%.1fs p90=%.1fs 最大=%.1fs"
      % (len(seg), sum(seg)/len(seg), statistics.median(seg),
         seg[int(len(seg)*0.9)], seg[-1]))
```
