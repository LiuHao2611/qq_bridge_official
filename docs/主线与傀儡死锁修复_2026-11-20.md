## 2. Bug 1：主线「强化玄重尺至 5 级」永久卡死

### 2.1 根因

```python
# 旧：进度只由事件累加
def main_progress(p, kind, n=1):
    t = current_main(p)
    if not t or t.get("kind") != kind:
        return
    p["main_progress"] = int(p.get("main_progress", 0)) + int(n)
```

`advance_task(p, "weapon")` 只在**真的点「强化」时**触发。于是：

* 玩家在 `main_idx` 还没走到第 4 章（斗尊之路）之前就把玄重尺练满 9 级 → 那 9 次强化全都不计数；
* 走到这一章时 `main_progress = 0`；
* 武器已满级 → 再也强化不了 → 事件永不再触发 → **进度永远是 0**。

「强化玄重尺**至 5 级**」是**状态要求**（到没到 5 级），不是次数要求。只有事件计数等于要求玩家「先读到这条任务、再去强化」，顺序错了就死。

### 2.2 修法

```python
def main_value(p) -> int:          # 渲染与提交统一读它
    t = current_main(p)
    n = int(p.get("main_progress", 0))
    if t.get("kind") == "weapon":
        n = max(n, int(p.get("weapon", 0) or 0))   # ← 状态值参与取大
    return n
```

* `main_submit()` / `task_submit()` 改用 `main_value()` / `task_value()`；
* `cmd_tasks` / `cmd_main_submit` / `cmd_task_submit` / `cmd_task_accept` 的进度显示同步；
* 支线同理；并且 **`task_accept` 不再发放已经达成的武器类支线**（否则满级者可以「接一次→交一次」白刷金币）。

事件计数那条路完全保留：新玩家边打边推，行为不变。

## 3. Bug 2：傀儡控火闸永远不过

### 3.1 根因

```python
# puppet_core.gate_fire_ctrl
cnt  = int(p.get("craft_count", 0) or 0)
high = int(p.get("high_grade_crafts", 0) or 0)
```

`grep` 全库：这两个键**只出现在测试里**（`test_doupo_puppet.py` 手塞），`core.craft()` /
`craft_batch()` 从来没写过 → 所有真实玩家的 `cnt` 恒为 0 → 控火闸对**任何人**都不过。

### 3.2 修法（两条腿）

**① 从此真实累加**（`core.craft()` + `core.craft_batch()`）：

```python
p["craft_count"] = int(p.get("craft_count", 0) or 0) + 1          # 每炉一次，成败都算
if 成品品阶 >= cfg.PUPPET_HIGH_GRADE_FROM("五品"):
    p["high_grade_crafts"] += 1                                    # 只有成丹才计
```

**② 老档用品阶下限兜住**（不改存档、不给谁补数据）：

```python
def craft_floor(p) -> int:
    # 从一品升到当前品阶共需 sum(ALCHEMIST[:alch][1]) 点炼药经验，
    # 每炉至少给 CRAFT_EXP(60)（失败给一半 → 真实炉数只会更多）
    return (sum(...) + alch_exp) // CRAFT_EXP

cnt = max(int(p.get("craft_count", 0) or 0), craft_floor(p))
```

这是**能证明的下限**，不是估算：七品必然 ≥ 238 炉。你现在算出来 255 炉。

「高阶丹 ≥ 1 枚」对老档无法回溯（字段历史上没写过），所以：**老档且品阶 ≥ 七品时视为满足**——
走到七品必须炼 238 炉以上，火候本身已经被证明了。

**③ 报错写出差额**：`火候不济，须多炼药（累计炼制 3/20 次，五品以上丹药 0/1 枚）`
——旧版只写「须多炼药」，玩家看不出还差几次。

### 3.3 附带发现：② 在数学上蕴含 ③（设计冗余，未改）

灵魂境界闸要求七品；七品必然 ≥ 238 炉；控火闸只要 20 炉。
所以 **② 过 ⇒ ③ 必过**，控火闸事实上是个装饰。

两条出路（需要拍板，本次没动）：
* 把 ② 放宽到**六品**（让 ③ 成为真正的第二道）；或
* 把 ③ 换成不依赖品阶的东西（例如「用 N 种不同异火炼过丹」）。

原测试 `五道资格-控火 独立报红` 之所以能绿，是因为它手塞 `craft_count=0` 造了个现实中
不存在的画像。已改成三条真断言：新手仍报红 / 老档不被卡死 / 七品下限已过门槛。
