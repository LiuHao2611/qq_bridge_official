### 1.2 语料有三个脏点，先治再查（治理过程本身就是证据）

1. **同章抓了两遍，其中一遍章号被截断**。例：`0088.html` 标题「第八十章炼药师柳席」，
   `0089.html` 标题「第十章炼药师柳席」——同一章，后者被吃掉「八十」。
   → 若按章号去重，会留下**错的章号**；若按章名合并，会把 480 组重名章并掉，
   实测丢了 145 章正文。
   → 最终方案：**一个 html 出一个 txt，不做章号权威化**。引用时人工看同名两文件里
   章号大的那个（大的才是真的）。本轮只引用 6 句台词，逐条人工核对过。
2. **源站把「药」替换成「『药』」**（`炼『药』师`、`斗『药』`）。
   → 直接 grep「炼药师」命中 0 次。检索器对正文与关键词**同时做归一化**
   （去 `『』`、引号、空白）后再匹配，回填原文坐标。
3. **导航噪声混在正文里**。第一章 69 行里 27 行 <25 字，其中包含
   `"三段？嘿嘿，果然不出我所料，这个"天才"这一年又是在原地踏步！"` ——
   **按长度过滤会把最短的台词最先丢掉**，而台词正是本轮最需要的东西。
   → 改白名单排除（`斗破苍穹 / 必读推荐 / 上一页 / 下一页 / 目录 / 关于`…），
   不按长度过滤。

|---|---|---|
| **反差** | 先被全场嘲「废物」，再一句「莫欺少年穷」翻盘 | 败局先 🥀 嘲讽、再 🩹 鼓励；胜局先判词、再 🏅 吹捧 |

## §2 设计与实现

### 2.1 五段结构（每段与敌人数无关）

```
📍 第 N 章 · 区域　妖物 lvX-Y          ← 已有（2026-11-25 第一轮）
　〈取景铺垫〉                          ← 新增 CHAPTER_SCENE[13]
⚔️ 遭遇 N 敌——XX等N名拦在去路上。        ← 已有
　〈境界·体征，回合判词〉                ← 已有（第一轮）
💥 〈高光〉——〈高潮反应镜头〉            ← 高光已有，反应镜头新增 CLIMAX_AFTER
⋯ 略去中间 N 式常规攻防                ← 已有
[🧿 傀儡掠阵]                          ← 已有（条件行）
🎯 此战斩获/未克 …                     ← 已有
🏅 〈吹捧〉 / 🥀 〈嘲讽〉               ← 新增，同一位置互斥
🩸 代价 …                              ← 已有
[🩹 〈鼓励〉]                          ← 败局专属
　〈点睛台词〉                          ← 新增 CHAPTER_QUOTE
```

行数：胜局 10 行、败局 11 行，**1 敌与 5 敌完全一致**。

### 2.3 三个判定函数（都从既有数据推导，不手抄阈值）

* `war_tier(win, taken, hp_ratio, foe_max_lv, my_lv)`：
  **越级 > 无伤 > 大捷 > 惨胜/险胜**，顺序即优先级。
  越级判定 `敌最高等级 ≥ 玩家等级 + 2`。
* `drop_tier(names)`：药材按 `HERBS` 价盘三分位（92 种，阈值 = `prices[n//3]` /
  `prices[2n//3]`）；丹药/带纹丹 → rare；其余（强化石、傀儡料）→ common；
  多件取**最高**档。→ 白参（260）落 trash，九玄金雷（12000）落 rare。
* `quote_line(ch, seed, special)`：有台账就出台词（苦战/败局必出，其余 1/3 概率），
  否则回落旁白。**台词是白名单**，池外带引号会被守门打红。

### 2.4 字数：把 200 字闸改成 350（唯一一次放宽，理由与代价都写在这里）

用户要「铺垫 + 高潮 + 吹捧 + 嘲讽 + 鼓励」，塞进 200 字必然退回电报体。
但**上一轮用户真正在意的是「敌人再多也不膨胀、不刷屏」**，那条不变量原样保留：

| 不变量 | 改前 | 改后 |
|---|---|---|
| 与敌人数无关（1 敌 vs 5 敌字数差） | ≤24 | **≤24（未动）** |
| 行数与标记序列随敌人数不变 | 必须相等 | **必须相等（未动）** |
| 绝对上限 | 200 | **350** |
| 新增：每段恰好出现一次 | — | 新增守门 |
| 新增：单池长短极差 ≤4 | — | 新增守门（见 §3.3） |

实测：测试骨架 1 敌 245 字 / 5 敌 266 字（差 21）；最坏组合（5 敌 + 傀儡 + 高阶 +
败局 + 长掉落）304 字。350 留了 46 字余量。

## §3 守门与验收

### 3.1 新增守门（`tests/test_battle_text_rich.py`，22 → 36 条）

第二轮 15 条，落在七组：
13 章铺垫齐全且互异 / 铺垫真的跟 `story_chapter` 走 / 铺垫排在「遭遇」之前 /
胜局 🏅 与败局 🥀 互斥 / 垃圾掉落必走 trash 池 / 贵药材必走 rare 池 /
混合掉落取最高档 / 败局先嘲讽后鼓励 / 台词只来自台账 /
台词跟章节走（防「一律用第一章」的退化解）/ 台词不带元信息 /
越级优先于无伤 / 池长短极差 ≤4 / 第二轮 prove-it。

### 3.2 变异反证：12 → 21 组，全部被抓住

新增 M13–M21：铺垫不出场 / 铺垫与章节无关 / 胜局也出嘲讽 / 吹捧不看掉落成色 /
败局没有嘲讽 / 台词现编 / 台词忽略章节 / 池内长短失控 / 越级不优先。

```
MUTATION_TOTAL=21 CAUGHT=21 MISSED=0
```

`M20（池内长短失控）`是这轮最有价值的一条：它证明「池长守门」不是洁癖——
把一个池的某句拉长 40 字，1 敌 vs 5 敌的 24 字预算立刻会被吃掉。

### 3.3 为什么必须守「池长极差 ≤4」

骨架闸允许 1 敌与 5 敌差 24 字，而两者的轮换种子不同（`rounds`、`n` 都进种子）。
一个池里最长句比最短句多 14 字，单这一个池就能吃掉一半预算。
把极差按在 4 以内，等于让**以后加句子这件事本身是安全的**——
不用每次加文案都回去重算 24 字。
