# 命中 · 与闪避对冲的双向词条 ＋ 怪物隐藏战斗面板（2026-11-20）

## 1. 需求原话

> 「看看今天的调整，我要改一些东西，我觉得应该有一个和闪避对应的词条，
> 不然闪避太超标了」

追问两轮后用户定下的落点：

1. **命中落点**：双向命中属性（最彻底）—— 实际闪避 = max(0, 目标闪避 − 攻击方命中)。
2. **怪物命中来源**：
   > 「按照等级来，然后无论是小怪还是精英怪，还是 boos，都应该拥有和玩家
   > 一样的隐藏面板，这样战斗逻辑进行时才不会出现个别词条一边倒的情况」

## 2. 问题确认（先量，再改）

改动前逐级实测（`tmp/sweep_hit.py`，每级 100 场，遇敌口径与 `core.pick_monster` 一致）：

| 等级 | 玩家闪避 | 怪命中 | 实际闪避 | 胜率 |
|---|---|---|---|---|
| 45 | 42% | 0 | 42% | 97% |
| 63 | 64% | 0 | 64% | 98% |
| 81 | 79% | 0 | 79% | 98% |
| 102 | 80%（封顶） | 0 | 80% | 92% |

结论：**等级把闪避顶到 80% 封顶，而怪物连「命中」这个概念都没有** ——
怪物永远打不中闪避流，战斗结果只剩「玩家几回合打死它」。九星突破 BOSS 实测
`taken=0`（一整场没挨过一下）就是这条的极端形态。同时怪物既不会闪也不会暴击，
词条天平彻底一边倒。

## 3. 机制与唯一真源

### 3.1 一条公式，双向结算

```
实际闪避% = max(0, 目标闪避% − 攻击方命中%)
```

只做减法不做乘法：闪避堆到 80 也还是「80 − 命中」，算得出来的数才解释得清。
三条落地位置都必须扣同一个命中：

| 位置 | 谁被打 | 扣的是谁的命中 |
|---|---|---|
| `core.fight()` 的 `dodge` 阈值 | 玩家基础闪避 | 怪物的 `panel["hit"]` |
| `core._hit(atk_hit=...)` | 怪物的 `evade`（含身法词缀） | 玩家的 `core.hit_rate(p)` |
| `skill_effects.on_incoming(hit=...)` | 玩家**临时**闪避（卸力水镜一类） | 怪物的 `panel["hit"]` |

第三条容易漏：只对冲基础闪避＝给技能身法留一个白嫖洞。

### 3.2 玩家命中（`core.hit_rate`）

```
命中% = cfg.HERO_HIT(6) + 大境界序号 × cfg.HERO_HIT_PER_REALM(1.5)
        + bonus["命中"]（凝识丹）
```

**刻意不吃敏捷**。敏捷已经同时产闪避与暴击（`STAT_BATTLE_ROLE`），若命中也从
敏捷来，两边同速成长 → 命中永远把闪避抵平，"词条"等于没加（假属性）。
命中走独立轴：怪物侧只由等级决定，玩家侧靠后天投入。

### 3.3 怪物隐藏面板（`core.monster_panel(lv, kind, is_boss)`）

| 项 | 公式 | 封顶 | 精英 | BOSS |
|---|---|---|---|---|
| 眼力（命中） | `level_dodge(lv) − cfg.MON_HIT_RESIDUAL(50)` | 95 | 不加成 | 不加成 |
| 暴击 | `2 + 大境界 × 0.8` | 25 | ×1.20 | ×1.45 |
| 身法（闪避） | `3 + 大境界 × 1.6` | 32 | ×1.20 | ×1.45 |

三点设计意图：

* **眼力 = 该等级白拿的身法 − 残值**。`level_dodge(lv)` 就是「不含任何装备/异火、
  纯等级」的闪避点数（与 `dodge_rate` 同一条曲线，供同等级同身法）。所以同等级
  怪物正好抵掉「靠等级白拿的身法」，只留 50 点底子 —— **要真能闪，得靠异火/丹药
  堆过头**。这正是"闪避超标"的解法：白拿的那部分被收回，买来的那部分留着。
* **眼力不加精英/BOSS 系数**。加了就会把底子闪避也扒干净，九星突破这种必打关
  直接变必输（实测过 92% → 0%）。精英与 BOSS 的强度落在暴击与身法上。
* **面板绝不进 hp/atk 反解**。难度仍只由物种等级 / 塔层 / 周本层决定，
  面板只决定「谁打得中谁、谁打得疼」。守门 `test_panel_does_not_touch_reverse_solve`
  直接把面板调高再比对 hp/atk 必须一字不变。

### 3.4 怪击暴击：与伤害浮动共用一次采样

```python
_m_crit = m_crit > 0 and var > 0 and roll > 1.0 + var - 2.0 * var * (m_crit / 100)
```

`roll` 是那次采样的单调变换，判「落在区间顶端 2·var·c 内」等价于独立掷一次暴击
（概率精确等于 c），但**不多消耗一次 rng** —— 既有 200+ 条逐招快照的随机序列不被打乱。
代价：`cfg.MON_DMG_VAR = 0` 时没有浮动也就没有暴击（同一次采样的必然结果），已写在常量注释里。

## 4. 数值标定（都是量出来的，不是拍的）

### 4.1 野外主线（`tmp/sweep_hit.py`）

| `MON_HIT_RESIDUAL` | 最低胜率 | 越界等级数 | 高等级实际闪避 | 高等级均胜率 |
|---|---|---|---|---|
| 70（≈没改） | 73% | 20 | 70.7% | 96% |
| 60 | 73% | 10 | 60.7% | 91% |
| **50（采用）** | **73%** | **2** | **50.7%** | **87%** |
| 45 | 63% | 5 | 45.7% | 83% |

判据是 `_balance.py` 自己的机器口径（胜率 70%~99.5%、平均回合 2~10）。
定 50：再往下压（45）最低胜率破 70% 下限。
**改完 `_balance.py` 跑出「全部达标」（基线是 28 项越界）** —— 顺手把难度漂移也收了一截。

> ⚠️ 顺带修掉一个假数据源：`_balance.py::species_pool` 原来写「±2 级，取不到就
> 退到全表最后两只」，而物种表最低是 lv9 的嗜血鼠 → **1~6 级新手直接打 lv102
> 魂殿执事**，体检报告里 lv1-6 的 35%~52% 全是假的。已改成与 `pick_monster` 同口径
> （同境界窗口 → 最近 3 只）。

| 63 | 地魔老鬼 | 98% | 99% | 99% |
| 81 | 魂殿殿主·魂灭生 | 68% | 78% | 68% |

据此重标定 `BOSS_BREAK_HP_MULT 1.60 → 1.15`、`BOSS_BREAK_ATK_MULT 1.15 → 1.10`：
BOSS 原来只有「血攻倍数」，现在多了暴击/身法/眼力三项，强度已经从那头补上了，
再留 1.60 就是「必输」（实测 92% → 22%）。改完 12 档全在 35%~98%，
低阶档位原本 3%~23% 的必败也顺手修好了。

## 5. 玩家能拿到什么

* `bonus["命中"]`：新丹 **凝识丹**（五品，七叶花 2 + 紫叶兰 1，300 金，命中 +5%），
  与风行丹（永久闪避 +5%）成对 —— 闪避有了对冲词条，玩家才有一条「打高身法目标」
  的实路，而不是只能看着怪闪。
* 帮助卡「属性」组新增两行，写明 `实际闪避% = max(0, 我的闪避 − 对方命中)` 与
  「怪物同样有眼力/身法/暴击」。

## 7. 已知取舍（如实交代）

* **闪避在高等级仍然封顶 80**，所以「净莲妖火 +10%/级」这类投资在 lv75 以上会被
  封顶吃掉一部分（`80 − 50 = 30` 点残值 + 投资 → 想再高只能顶到 80）。这是改动前
  就存在的封顶问题，这次没有动它 —— 动它等于重画整条曲线。
* **怪击暴击是「重击」而非独立随机**：概率精确但伤害与浮动区间正相关（暴击那一下
  本来就偏高）。这是为保住 rng 序列不漂移付的代价。
* 战斗结果对闪避仍然敏感（胜率与"实际闪避"近似线性），所以 `MON_HIT_RESIDUAL`
  是**唯一的削弱旋钮**：想更狠就往下压，压到 45 就会破 70% 下限（表在 §4.1）。
* 三个依赖 pytest 的用例（`test_doupo_agent_bridge` / `test_doupo_code_explain` /
  `test_doupo_official_channel`）在运行时镜像里没有 pytest，本轮与本次改动无关，
  未执行。
