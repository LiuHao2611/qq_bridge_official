# 战斗回执文案重构 · 设计文档（2026-11-25）

> 范围：`src/plugins/doupo/doupo_text.py`（战斗段）+ `commands.cmd_fight` 展示段。
> 不含：战斗数值、概率、掉落、胜率、章节门禁（那些属 G1/G2，已于同日前一轮交付）。
> 一句话：**只换玩家读到的那几行字，一行逻辑都不动。**

---

## 1. 需求原文

> 「优化整个战斗回复内容，结合原著改，要结合当前玩家的境界，还有使用的技能，或者高阶傀儡，等等，胜利或者失败后给出不同的高反馈内容，别这么单调和乏味，要吊起玩家兴趣」
>
> 用户贴出的反面样本（改前真实回执）：
> ```
> ⚔️ 遭遇 3 敌——嗜血鼠等3名拦在去路上。
> 　20 回合，大捷。
> 💥 这一记【裂爪击】最重——992 点伤害落在要害。
> ⋯ 略去中间 44 式常规攻防
> 🎯 此战斩获 嗜血鼠等3名 · 修为 +13 · 金币 +16 · 白参×1、炎星石×2、厚土芝×1
> 🩸 代价 防御减伤后受伤 2475 · 气血 462 · 服药 4
> ```

拆成六条可验收项：

| # | 要求 | 落点 |
|---|---|---|
| 1 | 结合原著 | 境界体征取自原著设定（斗气纱衣/斗晶/斗气化翼/踏虚/帝炎） |
| 2 | 结合当前境界 | 首行判词带 `full_realm`（二星斗师）+ 体征短语 |
| 3 | 结合使用的技能 | 💥 行带招式名 + **品阶**（高阶/特殊才亮） |
| 4 | 结合高阶傀儡 | 新增傀儡掠阵行，取真实傀儡击条目 |
| 5 | 胜/败不同高反馈 | 胜三档（大捷/惨胜/险胜）+ 败两段（力竭判词 + 收场句） |
| 6 | 不单调、吊兴趣 | 见 §5 的措辞分档表 |

## 2. 改前状态（实测，不是推测）

`cmd_fight` 的展示骨架是 7 行，全部由 4 个函数出句：

```
📍 第 1 章 · 乌坦城·萧家后山　妖物 lv5      ← txt.chapter_line
⚔️ 遭遇 2 敌——嗜血鼠等2名拦在去路上。        ← txt.encounter_head 第 1 行
　4 回合，大捷。                            ← txt.encounter_head 第 2 行
💥 这一记【劈山掌】最重——3621 点伤害落在要害。  ← txt.battle_spot
⋯ 略去中间 5 式常规攻防                      ← cmd_fight 内联
🎯 此战斩获 嗜血鼠等2名 · 修为 +213 · 金币 +426 ← txt.battle_gain
🩸 代价 防御减伤后受伤 195 · 气血 5600        ← txt.battle_cost
```

四个具体毛病：

1. **判词只有「大捷」两个字**，不分满血碾压还是残血险胜，也不提境界。
2. **💥 行丢了品阶**——`log` 条目里明明有 `tier="高阶"`，但 `battle_spot` 拿的是拼接后的字符串，品阶在拼接时就被丢了。
3. **傀儡完全隐形**。实测：同一场战斗带天级傀儡 vs 不带，回执**逐字相同**（只有折叠数 5→9 变化），玩家看不见傀儡出了多少力。根因是 `_battle_highlights(limit=1)` 只看「伤害最高的那一条」，而傀儡击条目同样参与评选——一旦傀儡伤害最高，它就会抢到 💥 行，被 `_battle_line` 归因成玩家的「力量·武器」，**把傀儡的功劳记到玩家头上**。
4. **败局只有「力竭·斩k/n」**一个数字，且战果行还写着「此战**斩获**」——打输了说斩获，自相矛盾。

## 3. 不能破的闸（改之前先量出来的）

`tests/test_battle_encounter.py` 是 2026-11-16 用户「字数不能随敌人数膨胀」的落地守门，硬约束如下：

| 闸 | 值 | 现状 |
|---|---|---|
| 5 敌总字数（去换行） | ≤ 200 | 改前 167 |
| 5 敌 − 1 敌 字数差 | ≤ 24 | 改前 9 |
| 1 敌 vs 5 敌 行数 | 必须相等 | 7 = 7 |
| 1 敌 vs 5 敌 标记序列 | 必须相等 | `⚔️ 💥 ⋯ 🎯 🩸` |
| `💥` 出现次数 | 恰好 1 | 1 |
| `略去中间` 出现次数 | 恰好 1 | 1 |
| 逐敌展开痕迹 | 禁 `①②③`/「交锋」/「决战」/同时出现怪1+怪2 | 无 |
| 必留锚点 | 遭遇 / 力量\|敏捷\|防御\|斗气 / 修为 + / 金币 + / 怪0等5名 | 有 |

**结论：新内容只能「替换」或「条件新增」，不能无条件加行。**
条件新增必须满足「与敌人数无关」——1 敌与 5 敌要么都出现、要么都不出现。

## 4. 数据摸底：能拿到的真字段

先确认「文案想写的东西，数据里到底有没有」，避免写出空话。

`res`（`core.encounter` 返回）实测 key：

```
auto_pills, detail, devour, downed, drops, enemies, enemy_count, exhausted, exp,
fire_energy_gain, flame_drops, foe_hp_end, foe_hp_max, fortune, gold, hero_aid,
hp_end, log, mp_end, puppet_guard, rounds, taken, win
```

`res["detail"][i]`：`index, kind, log, lv, name, rounds, taken, win`

`res["detail"][i]["log"][j]`（单条出手）实测样例：

```json
{"dmg": 3621, "crit": true, "kind": "劈山掌", "skill": true, "move": "劈山掌",
 "tier": "普通", "notes": [], "heal_ratio": 0.0, "raw": 2825, "def_cut": 410,
 "hp_before": 5600, "mp_before": 2400, "mp_cost": 480, "foe_hp_before": 3721,
 "round": 1, "foe": "嗜血鼠", "hp_after": 5600, "mp_after": 1920, "foe_hp_after": 100}
```

傀儡击条目（`puppet=True` 时）：

```json
{"kind": "傀儡击", "dmg": 7965, "puppet": true, "helper": "天级·玄",
 "tier": 2, "skin": "金", "formation": 1}
```

取值接口：

| 用途 | 接口 | 实测输出 |
|---|---|---|
| 完整境界称呼 | `cfg.full_realm(lv)` | lv5→斗之气五段 / lv20→二星斗师 / lv103→斗帝 |
| 大境界名 | `cfg.realm_name(lv)` | 斗之气 / 斗师 / 斗灵 / 斗宗 / 斗帝（13 档） |
| 斗技品阶 | `log[*]["tier"]` | `普通` / `高阶` / `特殊`（`cfg.SKILL_TIERS`） |
| 傀儡档位 | `log[*]["tier"]`（int 0/1/2） | `cfg.PUPPET_TIERS` → 人级/地级/天级傀儡 |
| 傀儡皮色 | `log[*]["skin"]` | 铜 / 银 / 金 |
| 斗气耗尽 | `res["exhausted"]` | bool |

**一个必须记下来的坑**：`res["puppet_guard"]` 里**没有** name/tier/skin，只有
`{id, count, soak, taken, hp_left, hp_max, broken}`。傀儡的名字与档位只能从
`log` 的傀儡击条目取。另外 `log[*]["helper"]` 的值是「天级·玄」——
`puppet_core` 造名时把 `PUPPET_TIERS` 的「傀儡」二字截掉了，文案层要自己补回。

## 5. 方案

### 5.1 新增 `REALM_FIGHT_TAG`：13 阶境界体征（4 字/档）

取原著各阶的标志性体征，与 `CROSS_LINES`（破境旁白）同一套设定来源，但压到四字：

| 境界 | 体征 | 原著依据 |
|---|---|---|
| 斗之气 | 气机鼓荡 | 气旋未成形，气机在经脉里冲撞 |
| 斗者 | 气旋初凝 | 丹田凝出第一缕气旋 |
| 斗师 | 纱衣浮体 | 斗气凝液，斗气纱衣浮于体表 |
| 大斗师 | 斗晶映体 | 液态斗气凝成棱形斗晶、铠甲自肤下升起 |
| 斗灵 | 掌生兵刃 | 斗晶生刺，斗气凝成兵刃 |
| 斗王 | 翼展生风 | 斗气化翼，首次离地 |
| 斗皇 | 虚空下陷 | 天地同属性能量奔涌，足下虚空下陷 |
| 斗宗 | 踏虚而立 | 一步踏虚，脚下空间泛涟漪 |
| 斗尊 | 空间随念 | 斗气凝晶，空间随手而裂 |
| 斗尊巅峰 | 空间明灭 | 一呼一吸间空间明灭 |
| 半圣 | 法则低鸣 | 半步过生死界限，天地法则低鸣 |
| 斗圣 | 拳裂长空 | 拳可裂天、脚可碎地 |
| 斗帝 | 帝炎焚天 | 帝炎自燃，万火听令 |

为什么必须四字：首行要塞进「境界称呼 + 体征 + 回合 + 判词 + 收束」，
多一个字就顶 200 字闸（§7 有余量实测）。

### 5.2 `encounter_head`：判词分五档

```python
encounter_head(n, foes, rounds, win, killed,
               realm="", tag="", hp_ratio=1.0, exhausted=False)
```

| 情形 | 第 2 行输出 |
|---|---|
| 胜 · 气血 ≥50% | `　二星斗师·纱衣浮体，4 回合大捷——斗气未散。` |
| 胜 · 20%~50% | `　二星斗师·纱衣浮体，4 回合惨胜——气血翻涌。` |
| 胜 · <20% | `　二星斗师·纱衣浮体，4 回合险胜——一线之差。` |
| 胜 · 斗气耗尽 | 判词同上，收束改 `斗气枯竭`（不能再说「未散」） |
| 败 | `　二星斗师·纱衣浮体，4 回合力竭·斩1/3——气机溃散。` |

`hp_ratio` 由调用点算（战后气血 / 体力上限）；本模块不做数值计算，只出句。

### 5.3 `battle_spot`：品阶四档

```python
battle_spot(spot, tier="", move="")
```

| 品阶 | 输出 | 说明 |
|---|---|---|
| 特殊 | `💥 【特殊·天火三玄变】气机一沉，9000 点碾下。` | 亮品阶 |
| 高阶 | `💥 【高阶·劈山掌】气劲贯体，3621 点砸进。` | 亮品阶 |
| 普通/空 | `💥 【劈山掌】一记砸实，3621 点落在要害。` | **不写「普通」**——普通是缺省，每场刷是噪音 |
| 普攻 | `💥 一记拳脚砸实，2100 点落在要害。` | 0 斗气转普攻时不写「【普攻】」这种把系统词当招式名的写法 |

品阶从 `log` 条目**直传**，不从拼接后的字符串反解析（反解析必丢）。

### 5.4 傀儡掠阵行（新增，条件出现）

```
🧿 金皮天级傀儡·玄掠阵，补 1.6万 点。
```

- 只在 `log` 里**真有** `puppet=True` 条目时出现——不是「带了傀儡」就写。
  带傀儡但它一次没出手，写「掠阵」就是编造战果。
- 伤害取所有傀儡击的**合计**：单条只反映一回合，合计才是这具傀儡的贡献。
- 与敌人数无关 → 1 敌 5 敌要么都有要么都没有，不破行数闸。

### 5.5 高光评选剔除傀儡击（防抢功）

```python
hero_log = [it for it in all_log if not it.get("puppet")]
pup_hits = [it for it in all_log if it.get("puppet")]
hi, folded = _battle_highlights(hero_log, limit=1)
```

不剔的后果：傀儡伤害高时抢到 💥 行 → `_battle_line` 按「无 skill 字段」
走 `力量·武器` 归因 → 玩家看到「傀儡击 7965（力量·武器）」，以为是自己打的。

副作用：`folded` 变小（傀儡击不算「常规攻防」）。这是**更准确**的口径，不是回归。

### 5.6 败局收场 + 战果换词

- 新增 `battle_defeat()`：`🩹 气血枯竭，你被生生打退——这笔账，记下了。`
  只在 `res["win"] is False` 时追加，排在「代价」之后（先看清损失，再给不甘）。
- `battle_gain` 加 `win` 参数：败时动词由「斩获」改「未克」，
  数值与锚点词「修为 +」「金币 +」原样保留。

### 8.1 顺带发现的验收口径问题

`pytest tests/` 一次性跑会报 **22 个 collection error**：多个测试文件在模块顶层执行
`sys.modules["nonebot"] = 桩`，互相污染后面的文件。这是基线既有行为，不是本轮引入。

`src/plugins/doupo/test_*.py` 那 28 个文件也不是 pytest 用例，而是**自带 main 的脚本**
（末尾有 `if __name__`，输出 `XXX_TOTAL=n PASSED=n FAILED=0`）。用 pytest 跑它们会
一律 `ValueError: NoneBot has not been initialized`。

正确的验收口径是：

```bash
# ① tests/ 目录：逐文件跑（一次跑会互相污染）
for f in tests/test_*.py; do pytest "$f" -q; done

# ② src/plugins/doupo/：脚本方式
for f in src/plugins/doupo/test_*.py; do python "$f"; done

# ③ test_skill_display.py 例外，需 stub 插件
PYTHONPATH="src/plugins;tmp;." pytest src/plugins/doupo/test_skill_display.py -p _pytest_stub_plugin
```
