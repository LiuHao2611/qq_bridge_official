### 3.3 全量 pytest 的 22 个收集错误（既有问题，非本轮引入）

`python -m pytest -q` 在收集阶段报 22 个 `cannot import name 'get_driver' from 'nonebot'`，全部集中在 NoneBot 适配器相关测试文件（test_battle_encounter / test_budget / test_ops_* ...）。

对照实验：
- 单独 `pytest --collect-only -q tests/test_battle_encounter.py` → **28 tests collected，退出码 0**，同一文件在全量里却报错。
- 根因：`tests/test_bagview.py:47`、`test_battle_review.py:40`、`test_danwen.py:34`、`test_doupo_craft_batch.py:35` 等约 20 个测试文件在模块顶层执行 `sys.modules["nonebot"] = MagicMock()` 注入假模块；全量收集时假 nonebot 污染 `sys.modules`，后收集的测试拿不到真实 `get_driver`。这是项目长期存在的测试隔离缺陷，与本轮改动无关（本轮改的 12 个文件没有一个属于这 22 个报错文件）。
- 处理方式：本轮采用逐文件单独跑的方式验收，规避该既有污染；不擅自重构全量测试隔离架构（超出本轮范围）。
