## 0. 一页速览

| 维度 | 一句话结论 | 关键数字 | 证据/探针编号 |
|---|---|---|---|
| 设计内核 | 把「点一次→一行数字」变成「开炉→丹成异象」的仪式感 + 惊喜产出 | 3 个改造方向 | D04 / E01–E08 |
| 业务流程 | 保留现有「炼药看方→炼制 N 次→结果」链路，只在结算与反馈层加厚 | 5 段流程 | D05 |
| 操作成本 | 操作次数不变，批量入口已存在（≤10 炉/次） | 熟练后 2 次输入/批 | D06 / C01 |
| 消耗 | 药材 + 斗气成本已实现，本轮**不新增任何消耗** | 斗气 8%/炉、CD 60s | D07 / C03 |
| 概率 | 丹纹惊喜（20%→1%）+ **赐福随机池 6 选 1** | 丹纹 20%→1%；赐福 ≥10% | D08 / 探针1,3 |
| 耗时与疲劳 | 单次耗时不变；疲劳来自「结果无惊喜、无画面」 | 3 档进度表 | D09 |
| 产出 | 丹纹 = 额外 1 丹 + **限时/限次赐福**（属性+25% / 前3击×2 / 首击必暴击等） | 期望丹数 1.02~1.18 + 赐福 | D10 / 探针1,3 |
| ROI | **持平但有趣**：数值靠赐福给足，但用时间/次数严格封顶 | 前3击×2 → 单场 1.15~2.0× | D10 / 探针3 |
| 数值锚与上限 | 丹纹率锚品阶；赐福锚「限时/限次」而非无限叠加 | 赐福 CAP=次数/时长 | D11 / 探针3 |

**核心体验（一句话）**：
让每一次开炉都有「丹香四溢、丹纹浮现」的原著仪式感，成功时偶得上品丹，服下后除本效外再得一段 giving-plenty 的限时/限次赐福，而不是冷冰冰一行数字。

**不做清单**：
1. 不做「一炉多丹」的常驻保底——原著只有一炉一丹（E07），丹纹是**概率惊喜**不是保底产出。
2. 不改成功率、不改经验曲线、不改 CD、不改任何消耗——本轮只动「反馈层 + 概率惊喜层 + 赐福层」，避免反解既有平衡。
3. 不做离线挂机炼丹——与原著「极耗斗气、掌控火候」相悖（E05），工程成本也高。
4. 不新增「付费加速/付费丹纹」——不引入任何隐藏付费墙。
5. 不做九品后成长目标（Q3 拍板）、不做寻火引导（Q4 拍板）。

**红线**：
1. 所有玩家可见数字必须与实战结算同源（单一真源），卡面不得重算。
2. 玩家可见文案禁止出现「原著未载/游戏原创/考据/语料」等开发向术语。
3. 丹纹概率必须写进帮助文案公示；不搞隐藏概率。
4. 禁止把已落地的低阶经验递减（`CRAFT_LOW_EXP_FACTOR`）和七品灵魂境界闸改回去——那是防刷防膨胀的既有真源。

## 3. 设计内核

- **一句话内核**：让每一次开炉都有原著「丹香四溢、丹纹浮现」的仪式感与偶得上品丹的惊喜，而不是一行数字。
- **与已有模块的差异**：战斗拼「数值与战报」，炼药拼「养成与惊喜」；本模块抢的是「情绪价值」而非战力，不与战斗抢输出锚。
- **不做清单**：见 §0（不做保底一炉多丹 / 不改数值与消耗 / 不挂机 / 不付费）。
- **红线**：见 §0（单一真源 / 无开发向术语 / 概率公示 / 不回退防刷闸）。

## 4. 玩家业务流程

| 步骤 | 玩家动作 | 系统动作 | 可见反馈 | 失败/中断分支 | 状态落点 |
|---|---|---|---|---|---|
| 1 接触 | 发「炼药」 | 出丹方卡（分页、成功率、品阶） | 丹方卡 | 无火→提示寻火 | 无写入 |
| 2 准备 | 备药材、确认有火 | — | 丹方卡显示「需 XX 材」 | 药材不足→提示去买 | 无写入 |
| 3 执行 | 发「炼制 X N次」 | CD 检查、逐炉扣药材/斗气、判成败、掷丹纹 | 开炉旁白（新） | CD/斗气/药材不足→明确回执 | `last_craft`/`bag`/`mp` |
| 4 结算 | — | 累计丹/药渣/经验、晋阶判定 | **丹成结果卡**（新）：品阶、丹纹、成败、经验、晋阶、斗气 | 全程失败→结果卡显示药渣与鼓励 | `alch`/`alch_exp` |
| 5 再参与 | 看结果卡提示 | — | 卡底「再来 N 炉 / 去炼药」 | — | — |

- **首次接触路径**：新手发「炼药」→ 丹方卡引导 → 发「炼制 回灵丹」→ **结果卡**首次出现时附一句丹纹说明（可发现性）。
- **熟练后重复路径**：发「炼制 回灵丹 10次」→ 直接出批量结果卡，丹纹高亮。
- **前置条件**：持有任意火（E03 火种）、药材足、过 CD。
- **明确退出点**：步骤 3 提交前可取消（不发口令即无消耗）；提交后不可退（原著「一炉报废」，E07）。
- **中断恢复**：批量内药材斗气在提交时按炉原子扣除，中断（会话断）不回滚已炼炉——与现状一致，本轮不改。

## 6. 消耗与机会成本

| 资源 | 单次消耗 | 是否固定 | 每日/周期上限 | 来源 | 折合时间 | 失败是否退还 |
|---|---|---|---|---|---|---|
| 药材 | 按丹方 need | 固定 | 无 | 宝库买/任务 | — | 否（原著 E07 报废） |
| 斗气 | mp_max×8% | 固定 | 斗气池上限 | 自动回复 | 调息 | 否 |
| CD | 60 秒 | 固定 | 每炉批一次 | — | 60s | — |
| （本轮新增） | **无** | — | — | — | — | — |

- **扣费时机与原子性**：提交时逐炉扣，整批一次 `last_craft`；沿用现状，本轮不改扣费逻辑。
- **预算归属**：批量炉数上限 `CRAFT_BATCH_MAX=10` 在循环外钳制（`n=max(1,min(n,10))`），不会循环内重置（C06 已验证）。
- **零值合法性说明**：`CRAFT_MP_PER=0.08`、`FAIL_DROSS=3` 均为显式常量，未用 `or` 兜底；丹纹率 0 的档位（若有）必须显式判 `<=0`，不得被 falsy 吞掉。
- **机会成本对照**：同样药材炼凝血散，药材成本 240 金、成品买价 280 金、单炉价差 +40 金；炼三纹青灵丹价差 +1130 金（探针1）。→ 炼药是自给正收益玩法，丹纹暴击只增产出不增消耗，靠低触发率控通胀。

- **保底重置规则**：无保底，每炉独立，不跨批累积。

## 10. 数值锚与上限

- **锚点与理由**：丹纹率锚在**丹药品阶**（E08「品阶过高引发丹雷」+ E06 七品门槛）——品阶越高越稀有，惊喜率越低，符合原著强度直觉；不用绝对常数（会随进度稀释或膨胀）。
- **唯一计算函数**：丹纹判定应复用 `cfg.rate_for_recipe` 之外的**新增唯一函数** `cfg.danwen_rate(grade)`（反解/实战/卡面/帮助全部读它），禁止在渲染层重算。

```text

UPPER: 丹纹率 ≤ 成功率 × 0.20（低品），高品 ≤ 0.02
```

## 10.5 丹纹赐福系统（v0.2 用户拍板新增 · 本节为核心）

> 用户 21:31 原话要点：最高丹纹的丹药，**除本身药效外额外给一个特殊加成**，加成随机、**不低于 10%、要给足**，靠**限时或限次**平衡。例：任意战斗前三次伤害×2、第一次技能伤害必定暴击。

### 10.5.1 设计内核

丹纹不只是「多一颗丹」，而是丹药**品相的凭证**：带纹丹服下后，除原有的 hp/mp/exp/stat 等基础药效，还会解锁一段「丹纹赐福」——一段强但**有边界**的战斗增益。边界用「次数」或「时长」封死，所以数值可以给得很足（+100%~+25%），玩家不会觉得抠门，经济也不会膨胀。这直接命中用户「给多给足、靠限制平衡」的设计哲学。

- **[事实] 原著依据**：E03/E04「火种提升成功率与药效」、E09 丹纹品相、E08 高阶丹丹雷异象——原著本就把「丹药品相」与「超常效力」绑定。
- **[设计] 本作扩展**：把「品相更好」具象为「服用后获得一段限时/限次战斗赐福」，这是本作主动设计，非原著数值（U01/U06 已标）。

### 10.5.2 丹纹 → 赐福的触发链

```text
开炉成功 → 掷丹纹（按品阶 20%→1%）
  ├─ 未出纹 → 普通丹「回灵丹」（现状，逐字节不变）
  └─ 出纹   → 带纹丹「回灵丹·丹纹」(+1 颗，独立背包名)
                 → 服下时：先执行基础药效(剥离后缀复用 use_item)
                           再掷赐福 6 选 1(随机) → 挂限时/限次状态
```

### 10.5.3 赐福随机池（6 选 1，全部 ≥10%，给足）

| ID | 赐福名 | 效果 | 类型 | 边界（平衡旋钮） | 是否公示 |
|---|---|---|---|---|---|
| B01 | 焚天之威 | 每场战斗**前 3 次出手伤害 ×2** | 限次(按击) | 3 击/服，多场不累积 | 是 |
| B02 | 一击必中 | 每场战斗**首次技能伤害必定暴击** | 限次(按击) | 1 击/服 | 是 |
| B03 | 蛮牛之力 | 力量/斗气 **+25%**，持续 30 分钟 | 限时(分钟) | 30 分钟，同名刷新不叠加 | 是 |
| B04 | 疾风之势 | 敏捷/防御 **+25%**，持续 30 分钟 | 限时(分钟) | 同上 | 是 |
| B05 | 虎躯之固 | 体力(气血上限) **+30%**，持续 30 分钟 | 限时(分钟) | 同上 | 是 |
| B06 | 丹田盈溢 | 斗气上限 **+20%** 且开战时斗气回满 1 次 | 限次(按场) | 1 场/服 | 是 |

- **概率**：6 种**等权随机**（各 1/6）——[设计]，理由：用户要「全部随机、给足」，等权最简单透明、无隐藏权重。
- **下限**：所有效果 ≥ +10%（实际最低是 B06 的 +20%），满足用户「别低于 10%」红线。
- **复用真源**：B03/B04/B05 直接复用 `temp_buff.add()`（分钟时限 + 五维键 + 到期自然消失，见 temp_buff.py）；B01/B02/B06 用新模块 `danwen.py` 的**次数型**状态。

### 10.5.4 次数型赐福的状态与生命周期（新模块 danwen.py）

```text
p["danwen_charges"] = {
   "B01": {"n": 3, "src": "回灵丹·丹纹"},   # 剩余击数
   "B02": {"n": 1, "src": "..."},
   "B06": {"n": 1, "src": "..."},
}
```

| 字段 | 类型 | 初值 | 写入时机 | 清除时机 | 持久化 | 跨场 |
|---|---|---|---|---|---|---|
| `danwen_charges` | dict | 无 | 服带纹丹掷中次数型赐福 | 击数耗尽即删键 | players.data | 是（未用完跨场保留） |
| 击数扣减 | int | — | `_hit` 命中后 `n-1` | n<=0 删键 | 同上 | — |

- **退场**：次数耗尽自动删键；`store.get_player` 惰性清坏数据（镜像 temp_buff.sweep）。
- **回滚**：赐福只改战斗数值，不碰药材/金币；失败战斗也照常扣次数（已服用的代价）。
- **零值判空**：`n<=0` 视为无，显式判断，不用 `or`（避免合法 0 被吞）。
- **单一真源**：`danwen.py::pick()` 掷赐福、`consume()` 扣次数、`apply_to_hit()` 注入伤害、`merge_panel()` 注入属性——反解/实战/卡面全读它。

### 10.5.6 探针3：赐福数值实算（原样粘贴）
