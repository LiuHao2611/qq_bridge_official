> 「战斗中，任意回合内如果将要收到大额伤害，傀儡有较低概率帮忙抵挡伤害，傀儡要有血量和
> 护甲，越高级的傀儡，帮忙抵挡伤害的概率越高，同时血量和护甲也越高。明白吗，去深度调研
> 原著，还有类似机制的游戏设计方案和完整源码。优化傀儡协助战斗逻辑，既不能抢了玩家角色
> 风头，傀儡也不能发挥不出作用」

## 1. 原著怎么写的

检索脚本：`tmp/lore_puppet_guard.py`，语料 `斗破苍穹_全本.txt`（14.8MB / 6432 行），
5 组正则共 21 处命中。「第 N 处」是脚本的命中序号，后面的中文是**原文卷章标题**，
按标题回查即可核验，不必依赖编号。

### 1.1 傀儡确实会「替主人挡」（A 类，3 处）

- **第853处·识破身份**：「应该不会，**有地妖傀保护她**，若是出了事，那么地妖傀应该也是
  出了问题，但我现在却并没有感应到地妖傀有什么不对。」
  → 「保护」是原著明写的职能，不是我们发明的玩法。

- **第898处·逃命**：「巨爪声势极其骇人，而萧炎也是明白这东西的恐怖，**连地妖傀都是被其
  一抓下，差点彻底报废**，以他的身体强度，恐怕一捏下，**就得爆成一堆血肉**。」
  → 这一句同时给了两件事：**傀儡顶在前面**，且**顶一下的代价是自身近废**。
  换算成本作口径：挡伤会大幅扣傀儡气血，「大额伤害」的门槛必须存在（不然每次摸一下都挡，
  傀儡永远在报废边缘，等于每场都在修）。

- **第971处·大风暴**：「看来在先前的大战中，**硬接了魂厉不少强猛攻势**，不过所幸如今的
  天妖傀已是今非昔比，不然的话，恐怕身体早就承受不住的爆裂而开。天妖傀**略微有所受创**。」
  → 高阶傀儡能连挡多次仍只是「略微受创」—— 这正是「档位越高血量护甲越高」的原文依据。

### 1.2 挡得住，但挡不住全部（D 类：不抢风头）

- **第934处·爆发**：「虽说一个天妖傀，**尚还挡不住玄空子**，但先前那一击，却是令得后者
  失去了最后的机会。」
- **第920处·迎接丹雷**：「难道他还指望这**频临报废的傀儡**来对付这恐怖的五色丹雷么？」
  「**抗一两道**五色丹雷或许还行，可想要靠它**度过丹雷，无疑是痴人说梦**。」

→ 原著的定位很明确：傀儡是**一次半的保护**，不是免伤盾。直接决定了本作的两个旋钮：
`PUPPET_GUARD_LEAK = 0.35`（挡下后玩家仍自担 35%）与 `PUPPET_GUARD_CAP = 0.40`
（三具结阵也封在四成，永远不会变成稳定护盾）。

### 1.3 会坏，坏了就不能再打（B 类，15 处摘 4）

- **第952处·摘星老鬼**：「萧炎挥手将已经被**轰击得千疮百孔**的天妖傀收回，心中暗叹，
  这跟随了他许久的天妖傀，又是**频临报废边缘**了啊。」
  「他纳中的天妖傀被天冥宗的那位强者轰得**将近报废，已经不能够在用来抗敌**，但**修复天妖傀，
  便只能用雷霆之力**。」
  → 三件事一次给全：① 有耐久会掉；② **掉光后退出战斗**（`_pup_hp > 0` 那道门）；
  ③ 修法是雷霆 —— 与既有 `temper()`（雷淬）完全对上，不需要新造修复系统。

- **第1047处·进入古树**：「那**半圣傀儡**本就被打出众多裂缝的脑袋，**当场便是爆炸了开来**。」
  → 极端情况傀儡会被彻底打爆，支撑「一击 cap 打空」的实现。

- **第920处·迎接丹雷**：「那被五色雷霆击中的地妖傀，不仅未曾崩裂而开，反而那受损的身体，
  居然在雷霆暴闪间，**开始徐徐的修复**。」
  「**吸收雷霆之力的傀儡**，我当年倒是在一座远古遗迹中见过。」
  → 雷属性=修复，与 `PUPPET_TEMPER_PURITY` 同源。

### 1.4 原著没写的

`D 以傀儡之身/躯体 承受` 与 `E 傀儡 替死/自爆` 两组正则**零命中**：原著没有「傀儡替玩家
挡死」或「自爆断后」的写法。所以本作**不做**替死、不做自爆、不做「主人致命伤自动转移」——
只做「挡下这一次伤害的 65%」，超出的部分仍然打在玩家身上。这一点是刻意的克制。

## 2. 同类机制怎么做的

调研目的是找「参考区间」，不是照抄。五个样本，从简到繁：

| 作品/方案 | 核心机制 | 数值 | 对本作的启示 |
|---|---|---|---|
| **梦幻西游三维版**（召唤兽内丹） | 「高级守卫 / 高级庇护」替主人承担物理/法术伤害；「高级替身」承担控制 | **20% 几率**，且把主人受到伤害**降至 1 点** | 业内对「替主承担」的默认量级就是 **20% 左右** —— 本作三档 18/25/32% 与之同量级 |
| **Crystal Saga**（宠物） | 宠物吸收一部分伤害且**不可闪避** | **15%** | 比梦幻更低；说明「低于 20% 也算成立」，关键在触发时要有明确反馈 |
| **Path of Exile 2**（Loyalty 支援） | 固定减伤，无随机 | **10% 减伤** | 固定减伤最不易「有感」，本作不用 |
| **Idol Guardians**（护卫型随从） | 按定位分配吸收比例 | 坦克 **80%** / 平衡 **60%** / DPS **40%** | 80% 那种量级放到本作会直接抢风头（玩家变成观众），仅作上限参考 |
| **ai-rpg-engine 第54章 Companion Interception** | **完整计分公式**（本章有可运行源码） | 见下 | 唯一给出「为什么这次没挡」的完整状态机，最值得抄结构 |

ai-rpg-engine 的拦截概率不是常数，而是**打分后钳制**：

```
score = 8
      + floor(instinct * 2.5)              # 0 ~ 25
      + max(0, floor((will - 3) * 1.5))
      + floor(hpRatio * 8)                 # 0 ~ 8
      - 15  (若 HP < 25%)
      + floor((morale - 50) * 0.15)        # -7 ~ +6
      + role 修正                          # -12 ~ +15
      + 8   (GUARDED 状态)  /  -10 (OFF_BALANCE 状态)

FLEEING 状态 → 直接 0
最终概率 = clamp(score, 5, 90)   # 基线约 31%
第 1 个通过判定的盟友吸收这次伤害
```

它有三个设计值得吸收：

1. **残血时反而护不住**（`HP < 25%` 扣 15 分）—— 本作照抄了这个方向：
   `PUPPET_GUARD_HURT_AT=0.30` + `PUPPET_GUARD_HURT_MULT=0.5`，傀儡血低于 30% 时挡伤概率减半。
   原著第952处「频临报废…不能够再在用来抗敌」正好是同一件事。
2. **钳制在 [5,90] 而非 [0,100]**：永远留 5% 的意外、也永远不给 90% 以上的确定性。
   本作对应 `PUPPET_GUARD_CAP=0.40` —— 上限更低，因为傀儡不该比人可靠。
3. **概率是「状态×属性」的函数，不是常数**：本作简化为「档位 × 材料系数 × 残血惩罚 × 结阵」，
   不去引入 instinct/will/morale 这类本作没有的属性维度（那会逼玩家去刷隐藏数值）。

**没有采用**的：梦幻西游「伤害降至 1 点」的完全豁免。理由是它把护主变成「免死」，与原著
第934处「尚还挡不住玄空子」直接矛盾，也正是用户说的「抢了玩家角色风头」。

## 3. 设计推导

### 3.1 为什么是「挡 65%、留 35%」而不是全挡

原著三处证据（898 / 934 / 920）都指向「挡一部分」。全挡的问题不只是抢风头，还有一个
数值副作用：玩家承伤归零后，「防御」「减伤」「丹药」这些养成全部失去意义 —— 一个傀儡
把玩家的整条防御线架空了。`leak=0.35` 保证玩家**永远仍在挨打**。

### 3.2 为什么血量要「比玩家薄」

`PUPPET_HP_RATIO = (0.25, 0.40, 0.55)`。如果做成比玩家厚，血条就是纯展示数字：一场战斗
玩家最多挨 3 次，傀儡血厚到永远掉不完，「血量」这一栏等于没写。做成 1/4~1/2 之后，
人级挡 2 次就见底、天级能挡 6 次 —— 档位差异立刻可感，且与原著「千疮百孔/略微受创」
的分布一致。

### 3.3 为什么护甲不能按玩家防御比例

**这是本轮最大的坑，见 §5.1。**

### 3.4 为什么不做跨场持久化

`temper()`（雷淬）已是既有修复入口，`damaged` 列也存在。但若护主损伤跨场累积，玩家每打
两三场就得回去雷淬一次，节奏会被打断；而「耐久」这条设计的价值在**单场内**就已经成立：
杂兵战平均只挨 1.8 次（天级根本掉不完血），BOSS 战挨 5~6 次（人级会被打爆）—— 差距本身
就是玩法。故本轮：**气血按单场消耗结算，跨场恢复满值**；卡面上的气血是**能力面板**
（"我的傀儡能扛多少"），不是状态条。若后续要做跨场磨损，入口是 `damaged` + `temper()`，
不需要新表。

## 4. 数值口径（唯一真源）

全部在 `config.py` 护主段，`core.fight` 与 `puppet_core.guard_profile` 都读同一份。

| 常量 | 值 | 含义 | 守门 |
|---|---|---|---|
| `PUPPET_GUARD_THRESHOLD` | `0.06` | 单次伤害 ≥ 玩家气血上限 6% 才算「大额」 | `test_only_big_hit_triggers` |
| `PUPPET_GUARD_CHANCE` | `(0.18, 0.25, 0.32)` | 人/地/天每掷一次的挡伤概率 | `test_tier_monotonic` |
| `PUPPET_GUARD_CAP` | `0.40` | 结阵叠满后的硬上限 | `test_probability_config_sane` |
| `PUPPET_GUARD_LEAK` | `0.35` | 挡下后玩家仍自担的比例 | `test_guard_is_not_immunity` |
| `PUPPET_HP_RATIO` | `(0.25, 0.40, 0.55)` | 傀儡气血 = 玩家气血上限 × 此值 | `test_tier_monotonic` |
| `PUPPET_ARMOR_TAKE` | `(0.78, 0.68, 0.58)` | 傀儡受击**穿透率**，护甲由它反解 | `test_armor_is_reverse_solved_from_take` |
| `PUPPET_FORMATION_GUARD_STEP` | `0.06` | 结阵每多一具 +6 个百分点 | `test_probability_config_sane` |
| `PUPPET_GUARD_HURT_AT` | `0.30` | 傀儡血低于此比例 → 进入「护不动」状态 | `test_broken_puppet_stops_working` |
| `PUPPET_GUARD_HURT_MULT` | `0.5` | 上述状态的概率乘数 | 同上 |
| `MITIGATION_W` | `800.0` | 减伤曲线半值点（本轮新提为常量） | `test_armor_is_reverse_solved_from_take` |

**护甲反解公式**（`puppet_core.guard_profile`）：

```
armor = MITIGATION_W × (1 / PUPPET_ARMOR_TAKE[tier] − 1) × 材料系数
```

于是 `core.mitigation(armor)` 恰好等于 `PUPPET_ARMOR_TAKE[tier]` —— 无论玩家多少级，
挡一次都稳定吃掉挡下量的 78%/68%/58%。卡面显示的是「护甲 N（减伤 M%）」两个数，
因为护甲绝对值在双曲线上的含义不直观，减伤率才是玩家能感知的量。

**结算顺序**（`core.fight`，缺一步都会算错）：

```
怪出手 → 技能 → 暴击 → 心火 → fx.on_incoming（玩家闪避/减伤）
      → 【判大额】inc["final"] ≥ threshold ？→ 掷骰 → 扣傀儡血、改写 inc["final"]
      → hp -= inc["final"]
```

用 `inc["final"]`（玩家实收）而不是原始 `dealt` 判大额：玩家自己闪掉/减掉的部分不该
再让傀儡拿肉身去填。

## 5. 调参实录：两个只有真跑才发现的坑

### 5.1 护甲按玩家防御比例放大 → 高等级傀儡永不掉血

**初版**：`PUPPET_ARMOR_RATIO = (0.60, 1.00, 1.50)`，即护甲 = 玩家防御 × 系数。

真跑扫描 `tmp/scan_guard_armor.py` 量出来的结果：

| 等级 | 档位 | 护甲 | 减伤 | 单次挡伤占傀儡血 | 挡几次报废 |
|---|---|---|---|---|---|
| lv10 | 人级 | 199 | 19.9% | 40.7% | 2.5 次 |
| lv81 | 人级 | 3143 | 79.7% | 12.5% | 8.0 次 |
| lv81 | 天级 | 6736 | 89.4% | **3.0%** | **33.6 次** |

根因：玩家防御从 lv10 的 570 涨到 lv81 的 8982（**15.7 倍**），而 `mitigation()` 是双曲线
`800/(800+d)` —— 小数值区陡、大数值区饱和。反解发现：**低等级需要 ratio≈0.98、高等级需要
ratio≈0.03**，固定比例在数学上无解。

后果不是"数字难看"，而是**整条需求失效**：一场战斗玩家最多挨 3 次，天级要挡 33.6 次才报废
→ 血条永远满格 → 「血量和护甲」是死数据 → 玩家看不到傀儡在扛任何东西。

**修法**：放弃「按玩家防御比例」，改为**锚定穿透率再由 `MITIGATION_W` 反解护甲**（§4）。
修后各等级减伤恒为 22%/32%/42%，报废节奏 2.2/3.8/6.1 次，跨等级稳定。

### 5.2 整数截断让傀儡永远剩 1 点血

**初版**：

```python
_g_cap = int(_pup_hp / _g_mig)          # 向下取整
_g_take = min(_pup_hp, max(1, int(_g_soak * _g_mig)))   # 再向下取整
```

实测（lv60 人级，`tmp/dbg_broken.py`）：`taken=8599`、`hp_left=1`，**永远差 1 点打不死**。

两步向下取整叠加，让「刚好吸满」恰好落在 `hp − 1`。后果是 `_pup_hp > 0` 这道
「报废即停手」的门（原著第952处）**形同虚设** —— 傀儡会以 1 点血无限挡下去，
而且每次只能挡 1 点，变成「还在护主但完全护不住」的荒谬状态。

**修法**：上限走浮点（`float(_pup_hp) / _g_mig`），自损用 `math.ceil`。宁可多扣 1 点，
也不能出现既不死也不活的僵尸态。守门里有一条专门钉死「任何一场都不许停在 `hp_left == 1`」。

### 6.1 护主面板（`tmp/probe_pup_guard.py` A 段，结阵 1 具）

| lv | 玩家气血 | 人级 气血/护甲/挡伤 | 天级 气血/护甲/挡伤 | 护甲减伤（人/地/天） |
|---|---|---|---|---|
| 20 | 5,600 | 1,245 / 200 / 18% | 4,034 / 758 / 32% | 20.0% / 33.6% / 48.7% |
| 60 | 34,400 | 7,653 / 200 / 18% | 24,785 / 758 / 32% | 同上 |

护甲绝对值跨等级不变（**这是刻意的**：护甲锚的是穿透率，不是玩家防御，见 §5.1），
气血随玩家气血涨 —— 所以「越高级越厚」体现在气血与穿透率，不体现在护甲数字变大。

### 6.2 带/不带傀儡对照（同种子 60 场）

| 场景 | 承伤变化 | 回合变化 | 护主次数/场 |
|---|---|---|---|
| lv81 人级 | −8% | 4.50 → 4.58 | 0.4 |
| lv81 地级 | −23% | 4.50 → 4.18 | 0.5 |
| lv81 天级 | −29% | 4.50 → 4.00 | 0.5 |

注：承伤降幅里**混有「傀儡输出让回合变少」的贡献**，不能全记在护主头上。护主自身的
分摊比（口径：`soak / (soak + 玩家实收)`，与守门测试同源）实测 **40% / 42% / 44%**
（人/地/天），红线是 50% —— 所以**不要再提 `PUPPET_GUARD_CHANCE`**，那会直接摸到红线。

### 6.3 战报可见性（`tmp/verify_guard_render.py`，强制抓到一次护主）

正是原著「差点彻底报废」的观感。

## 7. 已知边界与取舍

1. **单场消耗，跨场满血**。理由见 §3.4。磨损系统若要开，走 `damaged` + `temper()`。
2. **护主概率只由档位+材料+结阵+残血决定**，不看怪物类型、不看玩家属性。刻意保持简单：
   玩家能预期「我这具傀儡大概两成概率护我」。
3. **分摊比随战斗时长波动**。杂兵战挨得少，护主次数接近 0；BOSS 战挨得多，天级能护 3~5 次。
   这是设计意图（难战才有戏），不是数值不稳。
4. **`test_battle_review` 的 218 条逐招快照是 rng 红线**。任何在「无傀儡路径」上新增一次
   `rng()` 的改动都会让它们整片翻红 —— 这正是它们存在的意义，不要去"修"那些快照。
5. **容器内 `tests/test_doupo_boss_cast.py` 有 2 条既有失败**：`os.path.isfile(NOVEL)` 读的是
   Windows 盘符路径 `D:/AI/manju_agent/_novel_doupo_20261118/…`，容器里不存在。属环境性，
   与本轮无关；但也意味着那两条原著逐字守门在容器里一直空转。
