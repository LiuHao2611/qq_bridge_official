# 硬件行情模块重做（2026-11-19）

## 一、为什么要重做

用户反馈「每日行情数据取得非常差、极其不准确，差远了」，要的是**各大电商平台的价格波动 + 二手成交价波动**。

旧实现（`hardware/zol.py` + `daily.py`）的三个硬伤：

1. **数据源根本不对**：ZOL「参考报价」是媒体指导价，既不反映电商真实挂牌价，也不是二手成交价。
2. **取价口径有技术错误**：`best = min(hit, key=price)` 取当日样本最低价——一个异常标低价就能带偏整个型号。这是「极其不准」的直接根因。
3. **覆盖极差 + 无历史**：CPU 直接 `cpu_models()` 返回空不采；frocloud 月度档案停在 2026-10-02（过期 48 天）；每日快照当天才加、涨跌全是首日基线。

## 二、别人怎么做每日行情（深度调研）

| 做法 | 数据源 | 能否容器落地 |
|---|---|---|
| B站/头条「显卡日报」UP 主 | 多源聚合（搜狐/什么值得买/ZOL + **vramglass 闲鱼快照**作二手基准） | 可复现，VRAMGlass 是公开机读源 |
| 腾讯云「每日比价工具」 | Web Search API 运行时搜「显卡日报」+ 结构化抽取 | 需云 API key；核心教训：**搜索必须运行时调用，写死第二天就错** |
| 闲鱼真实成交价 | ①官方开放平台(企业资质) ②逆向 mtop(动态 sign) ③Playwright 拦接口(要登录态) | 前两条门槛高；第三条**账号风控红线，容器不碰** |
| rentgpu / VRAMGlass | 公开页面、超时标 stale、波动>40% 不上榜、修订留痕 | ✅ 免费、无登录、可机读 |

结论：**VRAMGlass 是唯一同时满足「无需登录 / 容器可跑 / 电商+二手 / 带真实历史波动」的源，且是 UP 主同款二手基准源。**

## 三、新数据源：VRAMGlass

- 站点：vramglass.com，服务端渲染，公开 HTML 内嵌 JSON，无需登录/key。
- 三市场独立中位价：`xianyu`（闲鱼二手挂单）、`ebay`（美国站在售）、`amazon_jp`（日亚商品主报价）。
- 粒度：约每 6 小时一个价格点，历史自 2026-09-04（首页表格另带 24h 涨跌 + 30d 走势）。
- 官方口径：**在售挂单中位价，不是成交价**；有效样本<3 不发布价格。本模块照此如实标注，绝不冒充成交价。

### 机读入口

- `/zh` 首页表格：全部型号的最新价 + 24h 涨跌 + 挂单数 + 30d polyline（**一次请求覆盖全市场**，总览用它）。
- `/zh/gpu/<slug>?market=...`：单型号详情，`<script type="application/json" data-price-points>` 全历史 + `data-share-image-data` 摘要（单型号卡用）。
- 某市场无报价时页面只有「暂无报价」→ 本层返回 `None`，卡面如实显示「— 暂无报价」，不伪造。

### 实拍抓到并已修的两个真问题（2026-11-20）

1. **专业卡混进 DIY 榜**：`_CONSUMER_PREFIX` 含裸 `Radeon `/`Arc `，且只查前两 token 的 `PRO`，
   于是 `RTX PRO 6000`/`RTX 6000 Ada`/`RTX A6000`/`Radeon AI PRO R9700`/`Radeon PRO W7900`/
   `Arc Pro B60·B65·B70` 全被当消费级，还占了涨跌榜。收紧为「任意位置出现 PRO/ADA、
   或形如 `RTX A6000` 一律剔除」后：59 → 27 款，榜上只剩真消费卡。
2. **时间轴末位被吃**：`"m": p.label[5:16]` 假设 ISO 格式，实际上游是「2026年11月19日 12:00」，
   多一个「日」→ 卡面印成「11月19日 12:0」。改为 `_short_time()` 正则去年前缀，
   并给区间文字加省略宽度上限，防撞左侧 Y 轴刻度。

### 菜单卡几何（`footer_block` 治不了贴纸压字）

补「DIY 硬件行情」分组后，末行说明被右下角星形贴纸压住。实测得出结论：

- 正文底 = `h - F - 7`，贴纸顶 = `h - 205`（F=`footer_block`，h 随 F 等量增长）
  → **加大 F 只是等价平移，永远差同一段 198px**，实测要 F 加到 246 才够，代价是 200+px 空白带。
- 结论：贴纸压字只能**缩短文案**解决。`footer_block` 40→64 只解决「页脚压正文」那一件事
  （正文底 h-47 vs 页脚 h-44 = 重叠）。
- 最终文案：`硬件行情 9070XT` / `三市场：中位价+走势`。几何自检 0 条被压、页脚 19px 间距。
  示例从 `5090` 换成 `9070XT` 是因为 `5090` 会命中 3 个型号（5090 / 5090 D / 5090 D V2），
  菜单示例必须一次就能出卡。
