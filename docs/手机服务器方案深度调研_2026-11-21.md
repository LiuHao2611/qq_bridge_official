# 手机当 24 小时服务器——深度调研与落地方案

> 时间：2026-11-21
> 目标设备：小米 6（sagit / 骁龙 835 MSM8998 / 6GB / UFS）
> 目标：qq_bridge + NapCat 在手机上独立 24h 运行，局域网 + 外网可访问，SSH 维护，手机放一边不连电脑。
> 结论先行：**放弃 pmOS 主线内核，改走 LineageOS(Android) + Termux 原生 Python**。qq_bridge 是纯 Python 栈，arm64 基本不用重构。

---

## 一、根因：为什么 pmOS 这条路必须放弃

不是配置问题，是**上游内核维护问题**，短期内修不好：

| 阻塞项 | 实测证据 | 性质 |
|---|---|---|
| WiFi | 主线内核 6.0 无 `wlan0`；ath10k remoteproc `segment outside memory range` / `node with id 0 not found in QRTR bus`；官方 issue `postmarketOS/pmaports#2536` 多人确认 sagit 长期无 WiFi | 上游主线内核已知 bug，非本机个案 |
| USB 网卡 | 内核未编译 `drivers/net/usb/`，`CONFIG_USB_XHCI_HCD/EHCI_HCD is not set`，手机只能做 USB device 不能做 host | 内核编译选项缺失 |
| 独立联网 | 上面两条都死 ⇒ 只能 USB NAT 连电脑，与"手机放一边"硬需求冲突 | 推论 |

一句话：pmOS 主线内核把 sagit 的无线能力砍没了；sagit 在 pmOS 已是 `device/archived`（unmaintained）。**继续在这上面调 WiFi 是浪费时间。**

## 二、别人怎么做手机服务器——调研共识

查证来源（均已实际抓取）：

1. mgks.dev《Running a Personal VPS on a Phone》—— 最贴近本任务。作者明确写：**先试 postmarketOS 是错误路线**（WiFi/蓝牙/硬件加速全 broken），最终落到 **Android as the Foundation + Termux**。
2. GIG OVH《A pocket-sized server: an old smartphone instead of a mini-PC》—— 开机链 `Android boot → always-on VPN → Termux:Boot → runit → services in chroot`。
3. tryopenclaw.ai《OpenClaw on Android via Termux: the honest 2026 setup guide》—— 小米专项保活：关省电、查 Autostart、关 Phantom Process Killer、WiFi sleep、限充 80%。
4. positioniseverything.net《Turning Old Cellphones Into SBCs》—— 明确说小程序/SCRIPTS/SQLite/轻量 HTTP 适合手机；Docker/K8s/重数据库不适合。
5. termuxtools.com、macmyths.com、androidexperto.com —— 一致结论：**Termux 不是 Docker Engine**；proot 无真实 namespaces/cgroups；原生 Docker 需自编译内核。

**共识结论**：成熟路线不是纯 Linux 手机系统，而是 **Android（厂商内核）+ Termux 用户态**。厂商内核保证 WiFi/电源/蓝牙/蜂窝正常，正好补上 pmOS 的短板。

## 三、为什么是 LineageOS（而不是继续 MIUI 或别的 ROM）

查证（thecustomrom.com / minnallab.com / LineageOS 官方 wiki / download.lineageos.org，2026-11-21 抓取）：

- sagit 有 **LineageOS 官方支持**，当前 **22.2（Android 15）**，维护者 ArianK16a、Nanhumly，**每周 nightly**（最新 2026-11-13），安全补丁 2026-10-01。
- 内核 **4.4 downstream**（不是主线 6.0）—— WiFi 802.11 a/b/g/n/ac、蓝牙 5.0、蜂窝、电源管理都是厂商调校过的，**WiFi 正常**。
- 非 A/B 设备，recovery 走 recovery 分区，fastboot 刷。bootloader 已解锁（之前已解），可直接刷。
- 备选：LineageOS for microG（去 GApps）、/e/OS（Android 14，社区版）；但主线 LineageOS 更新最勤，选它。
- 结论：**MIUI 也行（厂商内核 WiFi 一样正常），但 LineageOS 更干净、无广告推送、无后台干扰，更适合当服务器宿主。**

## 四、Docker 问题——决定 qq_bridge 怎么部署

这是最容易踩坑的地方，单独讲清楚：

| 路径 | 可行性 | 证据 |
|---|---|---|
| proot-distro 里跑 Docker daemon | ❌ 不行 | proot 无真实 namespaces/cgroups/overlayfs，dockerd 起不来 |
| 原生 Docker（root + 自编译内核） | ⚠️ 理论可行，代价大 | 需 `CONFIG_OVERLAY_FS`/`CGROUPS`/`CGROUP_DEVICE`/`MEMCG` 等，LineageOS 默认内核缺；自编译内核 8h+，**OTA 后失效**（XDA Note8 案例、CSDN K20 Pro 案例一致） |
| **arm64 原生 Python 直跑** | ✅ 推荐 | qq_bridge 是 NoneBot2 + SQLite + Pillow，纯 Python 栈；pip 装依赖即可，arm64 兼容好 |

**结论：手机上不要跑 Docker。** qq_bridge 直接以 arm64 原生 Python 进程运行，比容器更省内存、更少兼容层、更稳。你担心的"代码编译不兼容要重构"——好消息是**基本不用重构**，Python 是解释型，`requirements` 里的纯 Python 包在 aarch64 上直接装；唯一要盯的是个别带 C 扩展的包（Pillow/nonebot 生态一般有 aarch64 wheel，装不上再单独处理）。

现有 Docker 镜像（amd64）不能直接用，但**不用它**即可，不是障碍。

## 五、关键发现：NapCat 也能搬到手机（手机才真正独立）

这是决定"手机能否放一边不连电脑"的核心依赖。查证结果：

- NapCat 官方提供 **Termux 安装脚本**（NapNeko/NapCat-Installer）：
  `curl -o napcat.termux.sh https://nclatest.znin.net/NapNeko/NapCat-Installer/main/script/install.termux.sh && bash napcat.termux.sh`
- 社区还有 NapNeko/NapCat-Termux（ZeroTermux + bookworm + linuxqq）方案，支持 QQ 登录状态持久化。
- 已有完整实战：Termux 里同时跑 NapCat + 机器人框架，NapCat 配 **WebSockets 客户端**连本机反向 WS（`ws://127.0.0.1:<port>/ws`，消息格式 Array，心跳/重连 5000）。

⇒ **整条链（NapCat + qq_bridge）都能上手机**，Windows 电脑可以彻底关机。qq_bridge 的 OneBot V11 反向 WS 配置（原本连 `host.docker.internal` 那套）改成连本机 NapCat 即可。

## 六、网络访问设计

| 场景 | 方案 | 说明 |
|---|---|---|
| 局域网 | 手机连家里 WiFi，服务绑 `0.0.0.0:8081` | 路由器给手机留固定 DHCP 租约，局域网内 `手机IP:8081` 访问 |
| SSH 维护 | Termux openssh，端口 **8022** | `pkg install openssh` → `passwd` → `sshd`；局域网内 SSH |
| 外网私网 | **Tailscale** | outbound-only，无需公网 IP/端口映射，装了就能异地访问，最稳 |
| 外网公网 | **Cloudflare Tunnel**（cloudflared） | outbound-only，无需公网 IP，HTTPS；适合暴露 Web 面板 |
| 外网备选 | frp | 需要一台有公网 IP 的中转服务器；没有就优先 Tailscale |

三者都不要求手机有公网 IP 或做端口映射——这对家庭网络是关键优势。

## 七、保活与硬件红线（长期稳定的真正难点）

多篇资料一致警告：**Android 会杀后台、让设备休眠，对手机是特性，对服务器是灾难**。必须逐项配置：

**软件保活**
- Termux:Boot：开机自启（自启脚本拉起 NapCat + qq_bridge + 隧道）
- `termux-wake-lock`：持 CPU wake lock + WiFi lock，防休眠
- 系统设置：Termux 关电池优化、允许后台活动、允许自启动
- 小米专项：关省电模式、锁屏不清后台、检查 Autostart 白名单
- Android 12+：关 Phantom Process Killer / 子进程限制
- WiFi 睡眠策略设为"永不休眠"
- 进程守护：runit（推荐）或 screen/tmux；NapCat 和 bot 分开守护
- **外部存活监控**（必需）：定时任务心跳 ping 外部服务，挂了发通知——否则静默挂掉很难发现
- 掉电/重启恢复：Termux:Boot + 自启脚本保证重启后全自动恢复

**硬件红线**
- 电池：长期 100% 插电 + 温热 = 鼓包两大诱因。小米有"电池保护/智能充电"设到 80%；或定时插座每天通电 1-2h；终极方案是直供电小板（假电池，但失去内置 UPS）
- 散热：摘手机壳、放通风硬桌面、别压在路由器/机顶盒上
- 存储：手机 flash 不适合持续大量写入 → 日志 + SQLite 定期备份到外部（NAS/网盘/电脑）；qq_bridge 的 `data/warframe_mods` 约 736M、总 data 约 926M，注意别让 proot 层反复读写
- 数据：**必须外部备份**，这是手机服务器最大的长期风险

## 八、落地路线（分阶段，每阶段可验证/可回退）

| 阶段 | 动作 | 验收标志 |
|---|---|---|
| 0 备份 | 保存当前 pmOS 镜像 & SSH 凭据 & 数据现状；记录当前分区 | 镜像文件在 `D:\AI\tools\pmdocker\output\` 完好 |
| 1 下载 | LineageOS 22.2 sagit nightly + recovery/boot.img（校验 SHA256）；可选 GApps/Magisk | 下载 zip 与官方 SHA256 一致 |
| 2 刷机 | fastboot 刷 recovery → sideload LineageOS（非 A/B，recovery 到 recovery 分区） | 开机进 LineageOS，WiFi 能连、能扫到网络 |
| 3 装 Termux | F-Droid 或 GitHub **同一来源**装 Termux + Termux:Boot + Termux:API（签名必须一致） | `termux-wake-lock` 可执行 |
| 4 保活配置 | 关电池优化/自启、WiFi 不休眠、Phantom Killer | 息屏 10min 后 SSH 仍通、进程仍在 |
| 5 环境 | `pkg install openssh python`；`passwd`；`sshd -p 8022`；可选 proot-distro ubuntu | 局域网 SSH:8022 可登录 |
| 6 NapCat | Termux 一键脚本装 NapCat → QQ 扫码登录 → 配 WebSockets 客户端 `ws://127.0.0.1:8081/ws` | NapCat 面板显示已连接 / bot 收到消息 |
| 7 部署 bot | qq_bridge arm64 原生：拉代码 → pip 装 requirements → `DATA_PATH` 指到稳定目录 → runit/screen 守护 | bot 上线，52 条菜单口令可用，SQLite 落盘正常 |
| 8 网络 | Tailscale 登录（异地私网）；cloudflared tunnel（公网面板） | 手机断电脑后，外网 SSH/面板可达 |
| 9 监控备份 | 外部心跳监控 + 定时备份 data 到外部 | 人工拔电重启后全自动恢复、数据无丢失 |

**第 2 步是不可逆操作**（会抹掉 pmOS），且要下载约 1GB 镜像——执行前需要你明确拍板。其余步骤都可在刷机后逐步验证。

## 九、稳定性实话（不夸大）

- 多篇资料诚实指出：手机不是为 24/7 服务器设计的，不提供 uptime 保证，不适合业务关键服务。
- 但 qq_bridge 是**轻量、突发负载**（消息触发 + SQLite 读写 + 偶尔出图），正落在"手机能胜任"的区间。
- 成败关键不在 CPU，而在：保活配置是否到位 + 是否有外部监控 + 是否定期备份 + 电池/散热是否处理。
- 只要这四条做到，个人 QQ bot 长期跑在手机上是有大量成功案例的。
