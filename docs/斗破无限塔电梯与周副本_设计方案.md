# 斗破·无限塔电梯 + 周副本 · 设计方案（2026-11-17）

> 需求原话："调整爬塔模块，改成无限塔，挑战失败后，虽然会回到第一层，但是可以消耗金币
> 乘坐电梯直达上次失败层，直接满状态挑战，同时也不会重复获得之前挑战过层数的奖励，
> 然后再加一个周副本，只有7层塔，参考一下原著，这个周副本必须一次挑战到最高层，
> 否则奖励全部清零从头再来，这个周副本难度要根据人物等级和战力动态平衡。
> 当然只是周一的时候获取各个玩家等级和战力，给玩家在一周内提升战力的机会，
> 从而挑战通关周副本……新入道的另算。"
>
> 用户拍板（2026-11-17）：
> 1. 周副本失败清空**包括武器**；通关前所有奖励锁定不可用，失败即清空。
> 2. 难度口径：**周一快照锁定个人难度**（一周内不变）。
> 3. 新入道玩家：**固定新手难度档**。

## 二、无限塔电梯

### 2.1 目标语义

- "回到第一层"不变：失败后正常结束本轮，下次「爬塔」从第 1 层重开。
- 新增「电梯」：**消耗金币**，从上次止步层开始，且**满状态**（血量/斗气满、
  不带上一轮三选一临时增益）直接挑战该层。
- 重复层数**不再发奖**——包括金币经验和宝箱武器，都以"历史已结算水位线"为准。

### 2.2 玩家存档新增字段（写入 doupo.sqlite，挂载卷）

| 字段 | 含义 | 更新时机 |
|---|---|---|
| `tower_checkpoint: int` | 上次止步层（失败或收手都更新），电梯目标层 | 本轮结束（失败/收手/超时）时 `max(旧值, 到达层)` |
| `tower_paid_floor: int` | 已发奖水位线；≤ 该层的奖励不再发 | `tower_settle` 结算后抬高到本轮到达层 |

老存档缺省按 0 处理，首次结算自然迁移，无需一次性刷库。

### 2.3 奖励去重：水位线差值（关键公式）

现有 `clear_reward(f) = 120·f·(1+0.05f)` 是"从第 1 层连续爬到 f 层的累计奖励"
（非线性）。分段爬不能逐段相加，必须用**累计差值**：

```
本轮增量奖励 = clear_reward(本轮到达层) - clear_reward(tower_paid_floor)
结算后 tower_paid_floor = max(tower_paid_floor, 本轮到达层)
```

- 轮 1 爬到 10 层：`clear_reward(10)-clear_reward(0) = 1800` 金 / 1350 修为。
- 电梯到 10 层，轮 2 爬到 15 层失败：`clear_reward(15)-clear_reward(10) = 3150-1800 = 1350` 金。
- 两轮合计 3150 = 一口气爬到 15 层。**既不重复，也不缩水。**

宝箱同理：`tower_open_chest` 只在 `刚通过的层 > tower_paid_floor` 时才判定掉落；
电梯跳过的层不重开宝箱，避免重复刷武器/材料。`grant_weapon` 本身有"已拥有则不重复"
保护，但材料会重复，所以必须在入口处挡住。

### 2.4 电梯成本

```
elevator_cost(f) = max(200, int(clear_reward(f)["gold"] × 0.35))
```

| 目标层 | 累计奖励(金) | 电梯费 | 占比 |
|---|---|---|---|
| 10 | 1800 | 630 | 35% |
| 20 | 4800 | 1680 | 35% |
| 40 | 14400 | 5040 | 35% |

金币不够时提示差额，不开会话。常量 `ELEVATOR_GOLD_RATIO / ELEVATOR_MIN_GOLD`
放 `tower_data.py`，便于调参和单测。

### 2.5 满状态的定义

电梯走 `ts.STORE.begin(qq, floor=checkpoint)`：`floor` 预置到止步层-1，
`temp_hp/temp_mp = None`（战斗时取满值），`temp_bonus/temp_effects` 清空
（不带上一轮的三选一累积），种子换新。这样"满状态"= 满血满蓝 + 干净增益 + 从止步层单挑。

### 2.6 流程

```
爬塔（无会话）→ 第1层 ... 第N层失败
   → tower_settle 增量发奖、tower_paid_floor=N、tower_checkpoint=N、清会话
   → 提示「可发『电梯』直达第 N 层（花 X 金币）」
玩家发「电梯」
   → 校验 checkpoint>0、无活跃会话、金币足够
   → 扣金币 → begin(qq, floor=N-1) → 直接挑战第 N 层（满状态）
   → 胜利继续第 N+1 层（增量发奖只算超过 paid_floor 的部分）
```

## 三、周副本（7 层·一命通关）

### 3.1 核心规则

- **7 层固定**，不是无限塔的一部分，独立会话、独立入口。
- **一命通关**：第 1 层打到第 7 层，中途任一层失败 → 本轮**全部奖励清空**（含暂存武器），
  会话清空，下次从 1 层重来。中途**不能**"塔结算"式收手领部分奖励。
- **奖励锁定**：每层胜利所得金币/经验/材料/武器进入会话暂存区 `staged`，
  **不写玩家永久存档**；只有通关第 7 层才一次性 commit 入账。失败/退出/超时 → 暂存区全丢。
- **一周一次**：通关后记 `weekly_cleared_week = <ISO周>`，本周再打可挑战但不再给奖
  （提示"本周已通关"）。下周重置。

### 3.2 难度：周一快照锁定个人难度

- **快照内容**：玩家**完整战斗画像**深拷贝（`lv / weapon / weapons / equipped_weapon /
  bonus / flames / diyan / luck / learned / loadout / skills`），存 `p["weekly_snapshot"]`。
  只存 lv/power 不足以让 `monster_scaled` 反解，所以存画像本身。
- **快照时机**：以 **ISO 年-周** 为 key（如 `2026-W48`）。玩家本周首次进入周副本时，
  若快照 key ≠ 本周 key，取当前画像存为新快照并锁定；下周自动换快照。
  - 这是"周一快照"的健壮落地：等价于"本周锁一次"，周一一早打就是周一的值，
    周一没上线的玩家也不会失去快照（首次触发即锁定）。
  - 玩家在一周内修炼/升级/换武器变强 → 怪物仍按快照画像生成 → **越打越轻松**，
    正是用户要的"给一周时间提升战力去通关"。
- **难度生成**：第 n 层用 `monster_scaled(快照画像, species_n)`，
  `species_n` 有独立的 `weekly_hard(n)`（比无限塔略难）、层号 `快照lv + 偏移`；
  第 7 层 Boss（意象：天焚炼气塔封印的异火守卫，名字用原著角色，标注游戏设计）。
- **新入道固定档**：快照缺失（从未打过周副本/当周新入道）→ 用固定画像
  `WEEKLY_ROOKIE_LV / WEEKLY_ROOKIE_POWER`（常量，所有新手同一难度），
  不按个人属性。首次通关后写快照，下周进入正常个人档。
  - 判定边界写进文档：老玩家若从未打过周副本，第一次也走新手档（一次性保护），
    通关后即有个人快照——这是可接受的简化，避免误判。

### 3.3 奖励

```
每层暂存 = (clear_reward(n) - clear_reward(n-1)) × WEEKLY_REWARD_MULT(1.5)
第7层额外 Boss 奖励 + 宝箱武器（暂存，不即入包）
通关 commit：staged.gold/exp 入账、staged.items 入背包、staged.weapons 逐个 grant_weapon
失败/超时：staged 整体丢弃，会话清空
```

### 3.4 会话落盘（铁律）

新增 `weekly_session.py`：仿 `TowerStore`，`WeeklyStore` 原子写（tmp+fsync+os.replace）、
惰性 TTL、按 qq 隔离。路径 `cfg.WEEKLY_SESSION_PATH` 从 `DATA_PATH` 单源推导
（容器里 `/app/data/doupo/weekly_session.json`），不新开独立环境变量、不出现盘符路径、
默认目录排除在镜像外。加入 `tests/test_runtime_data_paths.py` 与

## 六、决策记录与风险

- **决策**：checkpoint 在"失败或收手"都更新（用户说的是失败层，但收手后想再冲的场景一致）。
- **决策**：周本快照用"ISO 周 + 首次触发惰性锁定"，比硬编码周一 00:00 定时任务更健壮。
- **风险**：快照存整个战斗画像会让存档字段增大（约 1–2KB/人），可接受。
- **风险**：新增 3 条菜单把菜单卡推高，需实渲染确认不破版。
- **不做**：周本不做中途收手领部分奖励（明确一命通关）；不做赛季/排行（用户上一轮已否）。
