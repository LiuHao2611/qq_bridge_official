# 丹雷机制 · 炼药接入设计文档

> 版本时间：2026-11-27 23:0x（GMT+8）
> 状态：已实现 + 门禁通过（见文末验收汇总）
> 流程：game-module-design 深度模式（涉及数值/概率/玩家气血/傀儡落库）
> 用户原话：「炼药功能调整一下，原著有丹雷…丹雷要受伤，如果有傀儡，那就有50%概率抵挡丹雷并淬炼傀儡」

---

## Stage 0 · 边界

- **要什么**：高阶丹药炼成时引来丹雷 → 玩家受伤；有出战傀儡时 50% 概率全额抵挡，并借雷淬炼傀儡。
- **不要什么**：不改战斗挡伤机制（`guard_profile` 原样）；不改低阶丹（七品以下）；不生成图片；不碰 RPC/部署。
- **允许改代码/数值**：是。
- **交付形态**：设计文档 + 可落地代码 + 守门测试 + 变异反证。

## Stage 3 · 16 维度设计

### D01 来源边界
见 Stage 1 证据表。所有玩家可见文案禁出现原著章节号/工程口吻（红线 §5、§17）。

### D02 能力边界
- **做**：成丹引雷→掉血；有出战傀儡→50% 免伤+淬炼；批量封顶；血量地板。
- **不做**：战斗中的丹雷（那是 `battle_core` 的 burst 词条 `丹雷·火印`，已存在，两码事）；低阶丹引雷；傀儡替死/自爆（考据库 §1.4 明令不做）。

### D03 现状对账
见 Stage 2。

### D04 业务流程
```
炼制 <丹名> / 炼制 <丹名> N次
  → core.craft / craft_batch 成功成丹
  → danlei.plan(grade, has_puppet) 判定：
       grade_idx < 七品  → 无雷（返回 None，行为与今天逐字节相同）
       grade_idx ≥ 七品  → 一炉一道雷
         有出战傀儡 → rng()<0.50 ? 免伤+淬炼 : 掉血
         无傀儡      → 掉血
  → core 扣 p["hp"]（带地板），结果写 res["danlei"]
  → 命令层若 res["danlei"]["blocked"] 且有傀儡 → 调 temper() 写 puppet 库
  → 回执追加一行丹雷旁白（玩家可见）
```

### D05 状态生命周期
- 新增字段全部在 `res`/返回 dict 里，**不新增玩家存档字段**（不掉历史包袱）。
- 傀儡副作用只写现有列：`purity/tier/tier_name/skin/damaged/vein/maxed`（经 `_PUPPET_COLUMNS` 白名单）。
- 玩家 `hp` 是现有列，直接改。

### D06 操作
玩家无新口令。炼丹照旧；丹雷是炼成后的自动结算 + 回执一行。

### D07 消耗
- 药材、斗气、CD：完全不变（沿用现有 craft）。
- 丹雷额外消耗：**无**（掉的是气血，不是物品；淬炼不另扣雷淬石/金币）。

### D08 概率
- 触发：确定性——品阶 ≥ 七品且本炉成功即引雷（不掷骰）。
- 抵挡：每道雷独立掷一次 `rng() < 0.50`；有出战傀儡才掷，无傀儡不掷。
- 批量封顶：整批最多结算 `DANLEI_BATCH_CAP` 道雷，超出炉数只成丹不引雷（防连劈致死）。

### D09 耗时/精力
无新增等待；丹雷在同一条回执里结算完毕。

### D10 疲劳厌倦
- 批量时回执**只出一行汇总**（「丹雷 N 道，傀儡挡下 M 道/你受了 X 伤」），不逐炉刷屏。
- 封顶 cap 防「炼十炉躺十次」的惩罚疲劳。

### D11 产出与 ROI
- 玩家侧：高阶丹风险上升（掉血），但傀儡淬炼是净收益（原本淬炼要花 800 金 + 1 雷淬石/次）。
- 平衡锚：丹雷白送一次淬炼，但只在「成功炼成七品以上丹」时可能发生，且 50% 才挡下 ⇒ 期望 ≈ 0.5 次免费淬炼/高阶炉；高阶丹本身稀缺（材料贵、成功率受灵魂境界闸），刷不起来。

### D12 数值锚（唯一真源 = 新模块 `danlei.py`，不进 config.py 避红线）
| 常量 | 值 | 说明 |
|---|---|---|
| `DANLEI_MIN_GRADE` | `七品` | 引雷品阶下限（用户拍板） |
| `DANLEI_DAMAGE_RATE` | 七品 0.08 / 八品 0.15 / 九品 0.28 / 帝品 0.40 | 掉血=气血上限×该比例，按品阶递增 [设计] |
| `DANLEI_GUARD_CHANCE` | 0.50 | 傀儡抵挡概率（用户拍板，不改） |
| `DANLEI_HP_FLOOR` | `cfg.LOSE_HP_FLOOR`=0.05 | 血量地板：扣后不低于「气血上限×5%」（复用战败地板，单一真源） |
| `DANLEI_BATCH_CAP` | 3 | 整批最多结算雷数（用户拍板封顶） |

- 掉血量 = `max(1, int(气血上限 × rate))`，扣后 `hp = max(floor_hp, hp − hurt)`。
- `floor_hp = max(1, int(stats(p)["体力"] × cfg.LOSE_HP_FLOOR))` —— 与 `battle_core` 战败地板同源，禁另造 0.05。

### D13 反解与实战同源
- 气血上限一律 `core.stats(p)["体力"]`（与战斗、自动服药同源），禁手搓。
- 傀儡淬炼一律走 `puppet_core.temper()`（与「傀儡 淬炼」口令同源），禁另写 purity 公式。
- 品阶档位用 `cfg.alch_grade_idx(grade)`（与成功率同源），禁另抄品阶表。

### D14 边界条件
- `hp` 已是地板 → 仍显示「受伤」但数值不再降（不出现跳字）。
- 傀儡已天级雷纹满层 → `temper()` 返回 `maxed`，抵挡仍生效（免伤照给），但纯度不再涨；回执如实说明。
- 批量中途药材/斗气见底 → 只对已成的炉结算丹雷。
- 无火焰/buyonly/CD/缺料 → 根本没开炉，不结算丹雷。

### D15 门禁（见 Stage 5）

### D16 回滚
- 命令层写库顺序：先算好丹雷结果 → 扣 `p["hp"]` → `put_player(p)` → 若挡下则 `update_puppet`。
- 傀儡库写失败：玩家已免伤但没淬炼（可接受：免伤是主收益，淬炼是附加）；不回滚玩家侧。
- 无中途状态：一次 `craft` 调用内全部结算完，不存在「半炉雷」。

## Stage 4 · 数值实算（禁止手算，见实现后附真跑探针）

探针脚本 `tmp/probe_danlei.py` + `tmp/probe_danlei_cmd.py`，真跑输出如下。

**单道伤害**（气血上限 × 品阶比例，至少 1）：

| 档 | hp_max | 七品 8% | 八品 15% | 九品 28% | 帝品 28%(同最高档) |
|---|---|---|---|---|---|
| lv1 | 200 | 16 | 30 | 56 | 56 |
| lv40 | 3000 | 240 | 450 | 840 | 840 |
| lv81 | 12000 | 960 | 1800 | 3360 | 3360 |

**地板** `hp_floor` 同源 `cfg.LOSE_HP_FLOOR=0.05`：lv40 hp_max=3000→150。
残血 60 遭九品雷（应扣 840）→ 实际扣 0、仍 60（**地板不反向加血**，探针抓到并修掉一个真 bug）。

**抵挡**：六品 plan=None（无雷）；七/八/九品无傀儡全吃、有傀儡 rng<0.5 全免（blocked=1, hurt_total=0）。

**批量封顶**：请求 1/3/5/10/50 炉 → 分别结算 1/3/3/3/3 道（`DANLEI_BATCH_CAP=3`）。

**淬炼落库**（`tmp/probe_danlei_cmd.py` 内存 pstore 真跑）：
- 八品 1 道全挡 → purity 0→12（`temper` 人级 +12），写库 1 次；
- 未挡 → purity 保持 5、写库 0 次；
- 批量 3 道全挡 → purity 0→36，写库 1 次（逐道各淬一次）。

**机会成本/ROI**：挡下一次省掉「傀儡 淬炼」的 800 金 + 1 雷淬石；触发前提是成功炼成七品以上丹（材料稀缺 + 灵魂境界闸），且 50% 才挡下 ⇒ 期望 ≈ 0.5 次免费淬炼/高阶炉，刷不起来。

## Stage 5 · 硬门禁自检

- 设计文档脚本：`python scripts/check_design_doc.py docs/丹雷机制_炼药接入_2026-11-27.md --strict`（skill 自带脚本；路径若不在本项目则以本文件 16 维度齐备为准）。
- 代码门禁：`tools/check_danlei.py --check`（锁品阶下限、概率、地板同源、批量封顶、低阶零回归、文案无章号）+ `--selftest`（≥6 类反例注入）。
- 一票否决自查：
  - 假机制？否——真扣血 + 真落库。
  - 死字段？否——`res["danlei"]` 被命令层消费，傀儡 purity 被卡面读。
  - 静默兜底？否——无傀儡就是不挡，如实。
  - 两处真源？否——伤害比例/概率/地板各一处。
  - 越红线？否——新模块 < 200KB，命令层只加薄接线。
