# QQ 官方机器人能力全景调研（2026-11-18）

> 对象：本项目 `qq_bridge_official`（nonebot2 + `nonebot-adapter-qq` 1.7.4，QQ 开放平台 **群机器人 / openid** 通道）。
> 方法：官方文档站 + 2026-11 的权威能力审计 + GitHub 官方/活跃仓库 + 社区实战踩坑，四条来源交叉核对。
> 每条结论尽量带出处；相互矛盾的口径单独标注，不编造 star 数和没查到的事实。

---

## 〇、一句话结论

你现在的「图片底部带按钮」（`msg_type=2` markdown 内嵌 `qqbot-media://` 图片 + keyboard 同段）属于**官方群机器人里做得比较深的一档**，但它只用了官方消息能力的约三分之一。

最值得补的 5 个，按性价比排序：

| 优先级 | 能力 | 为什么值得做 | 成本 |
|---|---|---|---|
| P0 | **消息引用** `message_reference` | 官方有现成字段，适配器 1.7.4（2026-11-04）刚补了 `ext_info.ref_idx`，群聊「回复哪句」是刚需 | 低 |
| P0 | **消息撤回**（2 分钟窗口） | 发错图/发错卡能撤；你项目的 `delete_msg` 已有实现但**只走 OneBot**，官方通道缺。注意只能撤自己的、超时必失败 | 低 |
| P1 | **语音/文件富媒体** | TTS 已合成出音频却降级成一句「当前通道发不了语音」；`send_file` 更是**写了但没接上**（见第一节），两处都是现成缺口 | 低～中 |
| P1 | **全量群消息订阅** `GROUP_MESSAGE_CREATE` | 现在只订阅「@机器人」和私聊，全量模式需申请权限，开了才能做群聊观察/自动应答 | 中（需权限） |
| P2 | **互动召回** `is_wakeup` | 用户主动聊过后 30 天内分 4 个周期各 1 条召回，正好适合斗破/修仙「回来继续爬塔」 | 中 |

不建议碰的：Ark / Embed 模板、频道类的公告/日程/置顶/表情表态/论坛/音视频事件——**那是频道机器人的能力，群机器人吃不到**（见第四节辨析）。

## 一、你已经用了什么（基线盘点）

以源码为准（不是文档写的愿望清单）：

**消息发送**
- `msg_type=0` 纯文本、`msg_type=2` markdown + keyboard、`msg_type=7` 富媒体图片（降级路径）。
- 官方「图片与按钮合一」已实现：图片先经素材管理 API 上传换 `qqbot-media://` 引用，内嵌 `![ #宽px #高px](url)`，与 keyboard 同段下发，用户看到一条消息（`official.py::_build_merged_card_segment`）。
- 素材管理三步 `prepare → PUT → complete` 已内置，含 100 张配额自愈、LRU、孤儿清理。
- 视频：`file_video` 段已接（`official.py` line 359–363）。
- **语音发不出去**：`media/send_record()` 检测官方通道后固定降级为文字提示。

**回复与交互**
- 被动回复：`msg_id + msg_seq`，群 5 分钟 / 每条消息最多 5 次，seq 严格递增（`passive_seq.py`）。
- 主动消息 + 每群每日额度闸门（`OFFICIAL_DAILY_GROUP_LIMIT`）。
- 按钮回调：`INTERACTION_CREATE` 事件 → `put_interaction(code=0)` ACK → 用 `event_id` 走被动回复（`qq_interaction.py`）。
- `on_message` 收群 @ / 群全量 / 私聊，`on_notice` 已挂交互事件；`mention_user` @ 人已接。
- 接入方式：WebSocket（`OFFICIAL_USE_WEBSOCKET`）+ Intent 事件订阅；openid 经 md5 映射为稳定负整数 pseudo_id。

**业务层**
- 42 条口令菜单、斗破/修仙双游戏、图片卡片渲染、AI 对话、TTS/ASR、爬塔/周本/紫卡等。

**写了但没接上（源码审计发现，值得优先修）**
- `media/send_file()` 构造 `Outgoing(file=...)`，但 `Outgoing` 数据类（base.py:57–72）**根本没有 file 字段**，`OfficialChannel.send()` 也无 file 分支 → 官方通道发文件必失败。图片/视频走了 `image_urls`/`video` 字段，唯独文件漏了。
- `delete_msg`、`set_group_ban`、`set_group_kick`、群成员查询等管理 API 全在 `__init__.py` 里走 OneBot `connector.call_action`，官方通道无对应实现。
- 群进人欢迎只监听 OneBot 的 `GroupIncreaseNoticeEvent`，官方 `GROUP_MEMBER_ADD` 没接。
- 私聊按钮被 `qq_interaction.py:167` 主动跳过（只处理群 INTERACTION_CREATE）。
- ASR 语音接收只从 NapCat 的 `voices` 取数据，官方语音消息未走通。

一句话：**发送侧和按钮交互做完了；撤回/引用/富媒体语音/召回/群事件基本空白，且文件发送存在一个已写未接的真 bug。**

## 二、官方支持、你还没用的能力（核心清单）

### 2.1 消息动作层

| 能力 | 官方接口 / 字段 | 你的现状 | 可行性 |
|---|---|---|---|
| **消息引用回复** | `message_reference.message_id`；非机器人消息取事件 `MessageScene.ext.msg_idx`，自己发的取响应 `ext_info.ref_idx` | 未接 | **高**：适配器 1.7.4 刚补 `ext_info.ref_idx`（commit c772c88, 2026-11-04） |
| **撤回消息** | `DELETE /v2/users/{openid}/messages/{id}`、`DELETE /v2/groups/{openid}/messages/{id}` | 未接 | **高**：但只有 **2 分钟**窗口，且只能撤机器人自己发的 |
| **富媒体语音** | 上传 `POST /v2/{groups|users}/files` 拿 `file_info` → `msg_type=7` 发送，支持图片/视频/**语音**/文件 | 语音 TTS 有产物但被降级成文字 | **中**：官方明确支持语音，你缺的是发送侧接线 |
| **富媒体文件** | 同上 | 未接 | 中 |
| **流式发送（单聊）** | `POST /v2/users/{openid}/stream_messages` | 未接 | 中：**群聊不支持流式**，只有单聊能用 |
| **编辑消息** | ❌ **官方根本没有这个端点**（接口索引里只有发送、撤回、流式、媒体上传） | 无 | **别做**：shenko 审计发现有适配器假报 `PUT /v2/messages/{id}`，那是幻觉端点 |
| **打字指示 typing** | ❌ 消息动作索引里没有独立端点 | 无 | **别做** |

> 关于 `msg_type=8` 图文卡片（card）：shenko 审计的请求体表里列了它，但官方 Markdown 主文档未明确展开，口径存疑，落地前须真机验证。

### 2.2 Markdown 表现层

官方 Markdown 支持的写法（`bot.q.qq.com/.../type/markdown.html`，2026-04-23 更新说明：单聊/群聊已对**所有机器人**开放，无需申请模板）：

- 标题 `#/##`、加粗 `**`、下划线加粗 `__`、斜体 `_/*`、加粗斜体 `***`、删除线 `~~`
- 链接 `[text](url)` / `<url>`、图片 `![text #宽px #高px](url)`
- 有序/无序列表、**列表嵌套**、块引用 `>`、水平分割线 `***`、多行（含零宽字符 `\u200B`）
- 内嵌 keyboard 按钮（`button action.type`：**0=跳转链接 / 1=回调事件 / 2=回填输入框**；你用的是 1）
- **不支持代码围栏**（会当普通文本行）

你目前只用了「内嵌图片 + 按钮」，正文标题/粗体/列表/引用/分割线/链接基本没用（卡片内容走图片渲染，纯文本回包是裸文本）。对文字类回包（帮助、状态、战报）是低成本的表现力提升。

另有 **Markdown 模板消息**（`custom_template_id` + `params`），你未用；迁移方案里明确「不做模板」，现在 Markdown 已全量开放，模板不再是必需。

### 2.3 事件与被动感知

| 事件 | 官方事件名 | 你的现状 |
|---|---|---|
| 群全量消息 | `GROUP_MESSAGE_CREATE` | Intent 里可订阅，业务目前主要走 @ 触发 |
| 私聊消息 | `C2C_MESSAGE_CREATE` | 已用 |
| 群成员加入/退出 | `GROUP_MEMBER_ADD` / `GROUP_MEMBER_REMOVE` | **未用**（你现在只处理 NapCat 的 `GroupIncreaseNoticeEvent`） |
| 机器人被拉入群/移出群 | `GROUP_ADD_ROBOT` / `GROUP_DEL_ROBOT` | 未用（可做自动问候/群登记） |
| 群消息接收/拒收 | `GROUP_MSG_RECEIVE` / `GROUP_MSG_REJECT` | 未用（可做推送开关感知） |
| 消息撤回事件 | 官方事件索引有 | 未用 |
| 表情表态 / 消息置顶 / 日程 / 论坛 / 音视频直播成员 | `GUILD_*`、`MESSAGE_REACTION_*`、`PINS_*` 等 | **全是频道场景，群机器人用不上** |

### 2.4 主动触达

- **互动召回** `is_wakeup`：用户主动对话后 30 天内分 4 个周期各 1 条；shenko 审计标为「未实现，能力表不宣称」。你的项目也没有。适合游戏回流。
- **主动群消息**：2026-06-22 起全量开放，但**必须群主在手机 QQ 群设置里打开「机器人主动在群聊内发言」**，且用户可单独关闭「允许主动发送」。你的日额度闸门管的是自己这侧，管不了平台开关。
- 私聊有严格的「先加好友/验证码绑定」要求，且未认证号主动额度很低（见第五节口径矛盾）。

### 3.2 从实战里提炼的「大佬用法」

1. **能力可达性审计法**（shenko）：不因为「文档说支持」或「代码里有方法」就宣称能力可用，逐条对齐官方文档 + 真机探测，差异写进证据文件。他们的收获是发现并删掉了一个幻觉的 `edit` 能力。→ 你加新功能前值得照这个口径过一遍。
2. **引用回复的地址来源**（adapter-qq / botpy）：普通消息用事件里的 `msg_idx`，自己发的消息用响应里的 `ext_info.ref_idx`——这两个字段来源不同，混用会引错消息。
3. **先 ACK 再处理**（botpy / 2libra / 你的实现）：互动事件必须秒回执，重活放后面，否则客户端 loading。
4. **主动消息优先被动通道**（zeroclaw 故障）：能带 `msg_id` 走被动就别走主动，既省额度又不会 40034102。
5. **群里不贴裸链接**（你的记忆 + 社区实战）：官方对未报备 URL 返回 `40054010`，你已经在 `send_video_link` 里处理了；社区做群服互通时也得做 URL 清洗。
6. **频控按接收方算**（社区群服互通实战）：单聊/群聊都有每分钟和每日上限，多消息要合并聚合发送——你已经用「每小时报表合并」规避了。

## 四、关键辨析：群机器人 ≠ 频道机器人

这是调研里最容易踩的坑，官方资料混在一起讲，但你的项目是**群机器人（openid / C2C / GROUP）**：

| 能力 | 频道机器人（GUILD） | 群机器人（你） |
|---|---|---|
| 公告、日程、置顶消息、论坛事件、音视频/直播成员事件、表情表态成员列表 | ✅ botpy 一堆 demo | ❌ 用不上 |
| Ark / Embed 结构化模板 | ✅ | ❌（你迁移方案里已决定不做） |
| Markdown 自定义消息 | ✅ | ✅ **2026-04-23 起全量开放**，这正是你「图片+按钮」的基础 |
| 富媒体图片/视频/语音/文件 | ✅ | ✅ |
| 全量群消息 `GROUP_MESSAGE_CREATE` | — | ✅ 需申请订阅权限 |
| 主动群消息 | — | ✅ 2026-06-22 全量开放，需群主开关 |

所以别照着 botpy 的 `demo_schedule` / `demo_pins` 去给群机器人加功能——那些端点群场景根本没有。

## 五、平台硬边界（核实过的数字，别踩）

**回复窗口**
- 被动回复：单聊 **60 分钟 / 每条 4 次**；群聊 **5 分钟 / 每条 5 次**；频道 5 分钟。（你现在按群 5 分钟 5 次实现，正确）
- 同一 `msg_id + msg_seq` 重复发会失败；`msg_seq` 必须严格递增（你已处理）。

**撤回**
- 只能撤自己发的消息；**超过 2 分钟不可撤回**（超时就别发请求，直接按规则拒绝）。

**主动消息频控**（shenko 审计引官方文档）
- 单聊：认证 `10/qps & 20/qpm`，未认证 `5/qps & 30/qpm`，`1000 条/用户/日`。
- 群聊：认证 `60/qpm`，未认证 `30/qpm`，单关系 `20/qpm`，`1000 条/群/日`。
- ⚠️ **口径矛盾**：另有 2026 社区文档说「私聊每月只能主动发 4 条」。两者冲突，可能是「未认证/未上线」与「认证后」的差别，也可能是旧口径。落地前请用你自己机器人真机测一次，别把任何一个数字当绝对。

**开关与权限**
- 用户可关闭「允许主动发送」；群主必须打开「机器人主动在群聊内发言」。
- 富媒体素材：**100 张上限**、滑动 90 天过期——你已经做过配额自愈。

**内容限制**
- 传了 `markdown` 后 `content` / `ark` 必须为空（互斥）。
- 不支持代码围栏；图片需公网 URL 或 `qqbot-media://` 引用。
- @ 写法：群 `<@member_openid>`、@全体 `<@all>`；频道 `<@!id>`——两套标记不通用。
- 未报备 URL 会被拒（`40054010`）。

## 六、建议的落地顺序

1. **先修 `send_file` 的假接口**：给 `Outgoing` 加 file 字段 + `OfficialChannel.send()` 加分支，否则文件发送在官方通道永远静默失败。
2. **升适配器到 1.7.4 最新**，直接拿到 `ext_info.ref_idx` → 引用回复（P0，改动最小、体感最明显）。
3. **加撤回**：把现有 OneBot 版 `delete_msg` 补上官方通道分支；发图/发卡后 2 分钟内可撤，超时显式报错不要静默吞。
4. **补语音发送**：官方支持语音富媒体，把 TTS 产物接到 `POST /v2/{groups|users}/files` → `msg_type=7`，干掉「当前通道发不了语音」的降级文案。
5. **评估全量群消息订阅**：需要先在开放平台申请权限；拿到后能做「没人 @ 也能听懂群聊」的观察能力。顺带把官方 `GROUP_MEMBER_ADD` 接进欢迎语。
6. **做互动召回**：30 天 4 个周期推「你还有塔没爬完」——正好接你现有的爬塔会话持久化状态。
7. 长线再评估单聊流式打字机、Markdown 富格式回包、私聊按钮；Ark/Embed/频道类永久排除。

每上一项都按项目纪律走：加真机/行为门禁 + 注入验证（把功能弄坏测试必须红）+ 容器内回归 + commit/push + rebuild。
