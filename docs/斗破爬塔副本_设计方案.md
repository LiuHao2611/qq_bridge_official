# 斗破爬塔副本 · 设计方案（2026-11-17）

> 需求："武器太少就不按宗门来了，换成副本掉落，但是要新增一个副本，爬塔类型的，
> 你先做深度调研，搞清楚一个好玩的多样化的爬塔副本如何设计，然后开始开发。"
>
> 用户拍板：① **无限层冲榜**（爬到死、记录最高层、难度递增、每10层 Boss、无中途退出奖励）；
> ② 武器**宝箱极低概率出，无保底**；③ 三选一**复用现有属性/effect**。

---

## 一、深度调研结论

### 1.1 外部方法论（roguelike 爬塔的共性）

| 原则 | 出处要点 | 本副本如何落地 |
|---|---|---|
| **锯齿压力曲线**，不单调堆数值 | 难度 climbs→drop→更高地 climb；每阶段开头低于上一阶段峰值，那个"谷"放商店/火堆/抉择 | 每10层一个周期：普通层→精英层(5)→Boss层(10)→掉落谷(结算/三选一)；跨周期基础难度再上一档 |
| **三档楼层** | 普通层热身/精英层针对弱点/Boss层机制识别，纯堆数值过不了 Boss | 普通层(1怪)、精英层(hard 更低+1词缀)、Boss层(原著反派+机制 effect) |
| **10 层一 Boss**，机制各异 | 护盾/再生/狂暴/分裂、阶段转换、弱点窗口，可学习可预测不可速通 | Boss 用现有 16 effect 组合出"persist 狂暴(empower)/再生(lifesteal)/反伤(reflect)/禁疗(debuff_heal)"等，每层 Boss 从池里按层号确定性抽 |
| **三选一战利品** | 选项影响后续容错与资源分配，决策权重高 | 每层胜利三选一，池子复用现有属性加成 + effect（用户拍板③） |
| **火堆/商店节点** | 高频交互节点增强节奏、缓解疲劳，避免重复感 | 每5层的"谷"给一次回血(火堆)或金币换增益(商店) |
| **账号级跨局累计** | 最高层、图鉴、成就跨局累计，"今天爬的每一层为下一局铺路" | `tower_best` 写存档、进排行榜；武器收集跨局累计 |
| **随机性在可控边界** | 玩家可观察记忆归纳提升确定性判断，死亡是认知校准而非纯坑 | 每轮用种子派生本层怪/Boss/三选一，同种子可复现；武器爆率固定且公开 |
| **单局时长** | 移动端 10–20 分钟、随玩随停 | 无限层随时可停（见"退出"语义），每层约 1 场战斗≈数秒，节奏由玩家掌握 |

### 1.2 本地系统（可复用 / 必须新增）

**可直接复用（零改动或极小改动）**
- 战斗内核 `core.fight()` / `monster_scaled()` / `_hit()` / `damage_schedule()`：塔怪用**虚拟 species** 走现有缩放，斗气跨战结转、暴击期望全部自动生效；
- 背包 `add_item/take_item/count_item`：武器/材料掉落入包；
- 会话范本 `duel_challenge.ChallengeStore`：按 qq 隔离、惰性超时、不落盘；
- 奖励 `_grant_reward()`、排行 `rank()`；机遇 CHANCE_EVENTS 里有现成"试炼之塔"文案可作叙事钩子；
- 卡片链路 `card._load_pic()` + `_render_list()`、按钮分发 `button_dispatch`。

**必须新增（调研发现的最大缺口）**
1. **武器持久化与生效**：`p["weapon"]` 目前只是玄重尺强化等级 0–9，**没有"持有/装备哪把武器"字段**；`core.stats()` 只算玄重尺。掉落的 14 把武器必须加 `weapons`(持有表) + `equipped_weapon`(当前装备)，并让 `stats()` 按装备查 `weapon_data.WEAPONS` 的四词条，否则掉落毫无意义。
2. 塔配置 `tower_data.py`：层类型/hard 公式/词缀池/三选一池/宝箱爆率。
3. 塔会话 `tower_session.py`（仿 ChallengeStore）。
4. 命令全套：`MENU_GROUPS` + matcher + keywords + `cmd_*` + 按钮 `_PLAN`/`CARD_ACTIONS` + 新卡模板。
5. 测试同步：菜单数 33→N（多处硬编码）、按钮 AST expected 表、出图像素、战斗平衡。

**平衡红线（不可碰）**：`MON_ROUND_RATIO` / `TTK_PLAYER` / `MON_DMG_VAR` 是全局胜率与时长总闸，塔的难度**只能通过虚拟 species 的 `hard`（及层系数）调**，不改全局常量；普通战斗的平衡测试（test_core TTK 3~7 回合）必须保持全绿。

## 二、核心玩法设计

### 2.1 入口与循环

```
爬塔  →  进入第1层（或无会话时重开）
  ↓
逐层战斗：第N层 → 胜 → 三选一战利品 → 是否继续？→ 第N+1层
  ↓（败 / 主动收手）
本轮结束 → 按到达层数结算（金币/经验/材料/宝箱）→ 记录 tower_best → 更新排行榜
```

- **无限层**：层数无上限，难度按公式递增（有下限，避免必死）。
- **死亡即结算**：`hp<=0` 时本轮结束，按"已通过层数"结算奖励。
- **主动收手**：`塔结算` 指令结束本轮并按当前层数结算（用户"无中途退出奖励"指不能反复进出刷奖励——本设计只在**本轮结束**时结算一次，且同轮重复进入不叠加）。
- **会话超时**：长时间无操作惰性清理；清理前按当前层结算一次，不吞奖励。
- **重开**：新一轮用新种子，怪/Boss/三选一重新派生。

### 2.2 楼层结构与难度曲线（锯齿）

| 层类型 | 判定 | 难度(hard) | 词缀 | 奖励 |
|---|---|---|---|---|
| 普通层 | `N%10 ∉ {0,5}` | 基准，周期内逐层降 | 无 | 三选一 + 宝箱判定 |
| 精英层 | `N%10==5` | 再降 0.02 | 随机 1 个战斗词缀 | 三选一 + 宝箱判定 + 额外金币 |
| Boss 层 | `N%10==0` | 再降 0.05 | 2 个机制 effect（按层号确定性抽） | 三选一 + **宝箱必开** + 大额金币经验 |

难度公式（层号 N，周期 c=(N-1)//10，周期内 p=(N-1)%10）——**以下为落地实际值**：

```
hard = clamp(0.93 - 0.015*p - min(0.18, c*0.01), 0.62, 1.00)
  + 0.04（普通层宽松）  -0.02（精英）  -0.05（Boss）
持续难度（无限层的终点，二次增长）：
  hp_mult  = 1 + 0.15 * ((N-1)/10)^2
  atk_mult = 1 + 0.15 * 0.9 * ((N-1)/10)^2
  → 第5层≈1.04×、第10层≈1.15×、第20层≈1.6×、第40层≈3.4×
塔怪攻击另乘 TOWER_ATK_SCALE = 0.18（单场→持久战，必须降攻）
  Boss 再 ×1.6、精英 ×1.25
层间歇息：每胜一层最多回 FLOOR_REST_HEAL = 12% 体力，
          且硬性不超过「本层实际损失 × 0.5」→ 跨层气血单调不增（战报只报实际回血）
怪 species.lv = clamp(player.lv + (c-1)*2, ...)   # 受 delta±20% 钳位
```

- `hard` 越小越难（= 怪斩杀玩家回合 ÷ 玩家斩杀怪回合），与现有 `monster_scaled` 口径完全一致。
- **为什么要 TOWER_ATK_SCALE**：`monster_scaled` 把任何怪都反解成「4~5 回合互杀」，
  单场合理；但塔是连战，不减攻会在第 1~2 层就把气血打空，永远见不到精英/Boss。
  降攻后难度由 hard（影响 TTK）与持续倍率承担。2026-11-17 二次调平后实测曲线
  （连战不选回血战利的保守值）：lv10 中位 7、lv30 8、lv50 9、lv70 13~14、lv100 19 层，
  终局剩 15~20% 气血——**能看到每一层都在掉血**，而不是满血刷塔。
- 硬下限 0.62 保证无限层也不会 100% 必死（配合 `MON_DMG_VAR` 仍有胜率空间）。
- **Boss 词缀用现有 effect 实现**，不改战斗内核：狂暴(empower 自身)、再生(hp_mult)、反伤(reflect)、禁疗(debuff_heal 玩家)、破甲(pierce)、吸攻(def_mult)。按层号选，可学习可预测。

### 2.3 三选一战利品（复用现有属性/effect，用户拍板③）

每场胜利给 3 个选项（同种子确定性抽，避免刷）：

| 类别 | 选项样例 | 实现 |
|---|---|---|
| 恢复 | 回春散：恢复 35% 体力 | 会话 `temp_hp` 加值 |
| 属性 | 力量/敏捷/斗气/防御 +X%（本轮有效） | 会话 `temp_bonus` 累加，战斗时并入 stats |
| 斗气 | 回气丹：斗气回满 / 本轮 mp 上限 +10% | 会话 `temp_mp` |
| 战斗 effect | 连击(chain)/破防(pierce)/吸血(lifesteal)/暴击率+ | 会话 `temp_effects`，注入本轮每次出手的 fx |

- 全部只改**本轮临时状态**（会话），不写玩家永久存档；本轮结束即清空。
- 效果维度全部取自 `skill_effects.EFFECT_LABELS` 现有 16 类，不新增 effect 类型。

### 2.4 武器掉落（宝箱极低概率，无保底，用户拍板②）

- 普通层宝箱判定：`CHEST_RATE_NORMAL = 0.25`（25% 开箱机会）；精英层 0.40；Boss 层 100%。
- **开箱内容**：`WEAPON_DROP_IN_CHEST = 0.08`（宝箱中 8% 出武器，即普通层期望 ≈2%/层），其余给炎星石/药材/金币。
- **无保底**：不设里程碑必得、不出重复武器（已持有则从武器池剔除，全收集后宝箱只给材料）。
- **按层解锁池**：低层只可能出前段武器，高层解锁后段（避免第1层掉血斧）；映射为 `min_level` 字段，层数 < min_level 的武器不进池。
- 掉落武器进 `p["weapons"]`，`cmd_装备 <名>` 切换 `p["equipped_weapon"]`，`stats()` 据此加四词条。

### 2.5 奖励结算

- 金币/经验：按通过层数线性+轻微非线性，`reward = base * (1 + 0.05*层)`。
- 材料：每层宝箱给炎星石/药材（复用 `HERBS`）。
- 最高层：`p["tower_best"] = max(old, 本轮层数)`，排行榜按此排序。

### 7.2 与初版设计的差异（均已按实测调整）

| 项 | 初版 | 落地 | 原因 |
|---|---|---|---|
| 塔怪攻击 | 与普通遭遇战同口径 | 额外 ×0.18（首版 0.42 后二次调平） | 连战不降攻必在 1~2 层耗尽气血（真实测出中位 1~3 层）；回血口径收紧后 0.42 只剩 6~7 层 |
| 难度增长 | 线性 0.035/层 | 二次 `0.15*((N-1)/10)^2` | 线性前期太陡（第4层就卡死）、后期又压不住强者 |
| 层间回血 | 10% | 首版 35% → 现 12% 且不超过本层损失 50%（只报实际回血） | 10% 抵不过每层受击；但 35% 会把单层伤害全盖掉（见 7.4） |
| 武器掉落 | 宝箱 8% | 保持 8%，但**按层解锁池**（玄重尺 1 层→血斧 12 层） | 避免第 1 层掉顶级武器 |
| 塔卡 | 计划新增 `doupo_tower` 出图卡 | **本轮做纯文本** | 战报是逐层刷新的长文本，出图反而不如文本好读；且避开新卡像素守门的面扩大 |

### 7.3 实现期抓到的两个真实缺陷（已修 + 已加守门）

1. **层数不推进**：`cmd_tower` 胜利后忘了 `st["floor"] = r["floor"]`，且 `TowerStore.begin()`
   返回的是副本没 `save()` —— 表现为「爬塔」永远停在第 1 层，可无限刷第一层奖励。
   守门：`test_commands.py` 的「爬塔 胜利后层数推进 / 能进入第 2 层」。
2. **宝箱按错层判定**：胜利时 `st["floor"]` 已推进到本层，宝箱再读 st 就按下一层算，
   第 10 层 Boss 的必掉宝箱变成第 11 层普通宝箱。改为显式传 `floor=`。
   守门：`test_doupo_tower.py::test_chest_rate_uses_passed_floor_not_state`。

### 7.4 第三个真实缺陷：气血看起来「每层重置」（2026-11-17 用户反馈后修）

用户原话：`看看日志，气血怎么好像没降低呢，是不是每次爬塔就重置状态了`

**先排除**：会话 `temp_hp` 是逐层延续的（`st["temp_hp"] = r["hp"]` 每层写回并 `save`），
不存在每层重置。逐层打印可证：第 2 层气血 = 第 1 层剩余血量。

**真因**：`FLOOR_REST_HEAL = 0.35` 每层白送 35% 上限，而单层实际掉血常常只有 10~30%，
回血把伤害**全部盖掉**。实测 lv60 连续 8 层每层都显示 `34400/34400`（满血），
玩家视角就是「没掉血 / 像重置」。这不是显示问题，是**平衡口径把消耗感抹掉了**。

**修法（两手一起）**：

1. 回血改成「双约束」：`rest = min(cap*0.12, 本层实际损失*0.5)`，无伤不回；
2. 塔怪攻击 `TOWER_ATK_SCALE 0.42 → 0.18`（回血不再兜底，必须同步降攻，
   否则 lv70 只剩 6~7 层）。
