## 铁律（先立后做）

1. **台词必须有原文出处**：每条 BOSS 台词标注章节号 + 原文引文。语料里没说的话**绝不代编**，
   宁可只用原文出现过的短句。全文已由子代理逐字交叉核对，未命中语料的一律不进卡面。
2. **快照只在内部、绝不对玩家露出**（2026-11-20 用户澄清原话：「战力快照要有，只是不要发出来，发出来会影响游戏体验」）：
   触发瞬间 `copy.deepcopy(p)` 锁一份快照，作为 `monster_scaled` 的反解基准 ——
   强度锁定在挑战那一刻，不受战斗中掉血/服药影响；`snapshot_power` 留在 `mon`
   和 `nine_star_breakthrough()` 返回里供内部校验。对外（命令文案/战报/卡片）
   **绝不输出快照战力数字，也不出现「心魔劫影」**：玩家看到的只有原著有名有姓的
   BOSS、登场引言、台词、技能与机制。旧版既把快照做成"打自己镜像"，又把战力印在
   文案里，两件事都已分别处理：身份换原著角色，数字留在内部。
3. **终局一个数**：沿用 `core.record_last_battle` / `fight()` 的 `hp_end` 单一真值口径，
   本轮不动数值层。
4. **机制复用现成效果系统**：`skill_effects.py` 已有 silence/stun/reflect/debuff_heal/
   debuff_atk/dot/def_shred，"恶心机制"优先挂在这些类型上，不另造轮子。

## §3 数据结构（config 新增，纯字面量）

```python
#: 每个 BOSS/精英怪的"角色包"：登场引言 + 台词 + 技能 + 机制。
#: quote 全部来自 §2 已核对原文；intro 为原文场景的引用式转述，标 source。
BOSS_CHARACTERS = {
  "魂殿摘星老鬼": {
    "title": "魂殿天尊",
    "source": "第一千一百九十九章 摘星老鬼",
    "intro": "既然老夫已经露面，怎还能让你们安然离去？",
    "quotes": [
      "在绝对的实力面前，这些都没有用",
      "凭借斗宗实力，便敢戏耍老夫，这可是老夫遇见的头一次！",
      "九幽魂手！",
    ],
    "skill": {"name": "九幽魂手", "chance": 0.28, "effect": "drain", "mult": 0.12},
    "mechanic": {"type": "silence", "d": 1, "chance": 0.25,
                 "desc": "黑雾锁魂——下一回合斗技被封，只能以尺肉搏"},
  },
  # ... 其余 11 个 + 精英怪，待台词核对完成后逐一填齐
}
```

- `intro`：**登场时插一条无伤害旁白 log**，沉浸式"突如其来的惊喜/惊吓"由它承载。
- `quotes`：技能施放时按 notes 带出；战败/胜利各有专属收尾台词。
- `mechanic`：复用 `skill_effects` 的 effect type；精英怪"一个技能 + 一个恶心机制"。

## §4 战斗日志接入点（core.fight）

- 战斗开始（`roll_hero_aid` 之前）插入 1 条 `{"kind": "登场", "speaker": name,
  "quote": intro, "dmg": 0}`；`_mark` 会给它补 round/foe/hp_after 字段。
- 怪物技能命中时，若该怪有 `quotes`，把台词并入 notes 的 `monster_quote` 字段
  （不改 kind/dmg，沿用已核对过的"技能并入 notes"口径，避免回看卡把一次攻击拆两行）。
- 机制在怪物出手那一次走 `fx.on_hit(effects, m_fx, p_fx, ...)`，挂到玩家身上；
  效果生效由 notes 呈现，数值仍由现有 system 结算。
- 逞强/失误/心火共鸣等既有条目不动。

### §7.1 野外 / 塔 / 周本角色包口径（补做「每一个精英怪和 BOOS」）

### §8.1 铁律新增第 5 条：玩家可见文案零元说明

### §8.2 登场三段式：剪影 → 报名号 → 接台词

原著写强敌出场从来不先报名，而是先给**一个能看见的画面**（黑雾、血发、锁链、
七彩光芒），再报身份，最后才让他开口。同类游戏（卡牌/回合制的 BOSS 入场）也是
「剪影 → 名字条 → 语音」三段。落地方案：

- 新表 `cfg.CHARACTER_APPEARANCE`（31 条）集中管理出场描写，`cfg.character_appearance(name)` 读；
  `monster_character()` 与 `make_breakthrough_boss()` 自动挂到 `ch["appearance"]`。
- `core.fight()` 的登场 log（`intro=True, dmg=0`）写两条 notes：
  `[appearance, intro]`；`intro` 若与 `appearance` 重复只留一条。

### §8.3 技能效果真落地：查 4 处，2 处是假、1 处是死代码、1 处方向错

用户质疑「只加了技能描述、效果没落地」。逐个用 `git show HEAD` 对拍核实：

| # | 声称的问题 | 实际核查结果 | 处理 |
|---|---|---|---|
| 1 | `poison` 只写 notes，不挂 DoT | **真 bug**：HEAD 里 poison 分支只算 `poison_dmg` 写进战报文本，`p_fx["dot"]` 从未被写，玩家血条不动 | 改成挂 `p_fx["dot"]`（`d=2`，`v=1.0`，`base=本次毒伤`）；同时**删掉**旧 `poison_turns` 计数器——两套并存会把两回合毒算成四回合 |

| 3 | mech 的 `dot` base 写死 1，每回合掉 1 点 | **假警报**：`skill_effects.on_hit` 的 dot 分支一律用本次命中伤害 `dmg` 作 base（`"base": max(1, int(dmg))`），根本不读 `e["base"]`；core 里那行 `_mech_eff["base"] = …` 是**死代码** | 删除死代码并留注释说明真开关在 `on_hit`；反证改成去改 `on_hit` 才报红 |
| 4 | `debuff_heal` 只压吸血，玩家主要靠服药 → 减疗无感 | **真 bug**：`_try_auto_pill()` 回血量没乘 `heal_mult` | 服药回血乘 `fx.heal_mult(p_fx)` |
